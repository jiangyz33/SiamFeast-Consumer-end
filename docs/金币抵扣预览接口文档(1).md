# 金币抵扣预览接口 + A 算法（分段累进）说明

> 日期：2026-07-05
> 适用端：C 端 APP / 收银端 / 门店端

---

## 1. 背景

旧版本的金币抵扣计算有 3 个 bug：

1. **算法错误**：`GetCoinDeductionConfig` 用 `ORDER BY id DESC LIMIT 1` 只取一条档位，按"单一 rate × 全部金币"算（如 42 × 1.6 = 67.2，产生小数）。运营实际业务规则是**分段累进**
2. **漏调 bug**：`UpdateUserOrder`（C 端改单）漏调 `deductionCfg`，直接 1:1 兜底
3. **老接口硬编码 bug**：`POST /api/v1/user-orders/calculate-coin-deduct` 直接 `coins × 1`，没调任何计算器，C 端 APP 调它就会得到错误金额（订单详情页显示 42 baht 而非 66 的根因之一）

修复后：
- 后端 4 处调用点统一走 A 算法（含老接口）
- 新增**预览接口** `/coin-deduction/preview`，前端结算页可直接调
- 老 `calculate-coin-deduct` 接口响应**新增 `max_deduct_percent` / `max_deduct_amount` 字段**，方便前端展示「本单最多可抵 ฿X」

---

## 2. A 算法（分段累进）

### 业务规则

DB `coin_deduction_configs` 表存所有档位，每档定义：
- `coin_amount`：一包多少金币
- `deduct_amount`：这一包抵多少铢
- `max_deduct_percent`：每单抵扣百分比上限

### 计算步骤

1. 把所有 active 档位按 **rate = deduct_amount / coin_amount** 降序排（最优档优先）
2. 对每档：`packs = remaining_coins / coin_amount`（整除下取），消耗 `packs × coin_amount` 金币，抵 `packs × deduct_amount` 铢
3. 剩余金币进下一档
4. 全局 `max_deduct_percent` 上限校验，触发则反算金币数（按最优档 rate）
5. 不超过订单金额

### 算法示例

DB 配置：

| id | coin_amount | deduct_amount | rate |
|----|----|----|----|
| 38 | 1 | 1.00 | 1.0 |
| 39 | 5 | 8.00 | 1.6 |

**用 42 金币**：
- 5-coin 档（rate=1.6）先用：42/5=8 包 → 用 40 coins，扣 64 baht，余 2 coins
- 1-coin 档（rate=1.0）后用：2/1=2 包 → 用 2 coins，扣 2 baht
- 合计：**66 baht（无小数）**

**用 11 金币**：
- 5-coin 档：11/5=2 包 → 用 10 coins，扣 16 baht，余 1 coin
- 1-coin 档：1/1=1 包 → 用 1 coin，扣 1 baht
- 合计：**17 baht（无小数）**

### 跟旧 bug 算法的差异

| 金币数 | 旧 bug（id DESC LIMIT 1） | A 算法 | 差额 |
|--------|---|--------|------|
| 1 | 1.60 | 1.00 | 0.6 |
| 5 | 8.00 | 8.00 | 0 |
| 6 | 9.60 | 9.00 | 0.6 |
| 11 | 17.60 | 17.00 | 0.6 |
| 42 | 67.20 | 66.00 | 1.2 |
| 137 | 219.20 | 218.00 | 1.2 |

差额规律：每跨过一次 5-coin 整数边界，多算 0.6 baht（1.6 vs 1.0 的 rate 差）。

## 3. 预览接口

### 3.1 C 端

```
POST /api/v1/coin-deduction/preview
Authorization: Bearer <consumer_token>
Content-Type: application/json
```

### 3.2 收银端

```
POST /api/v1/cashier/coin-deduction/preview
Authorization: Bearer <cashier_token>
Content-Type: application/json
```

> 两个端走同一 handler，行为完全一致。区分路径是因为路由组挂载了不同 role middleware（C 端 `consumer`，收银端 `cashier`）。

### 3.3 请求体

```json
{
  "coins_to_use": 42,
  "subtotal": 10000
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `coins_to_use` | int | ✅ | 用户想用的金币数（≥0） |
| `subtotal` | float | ✅ | 订单金额，扣券前（≥0） |

### 3.4 响应体

```json
{
  "coins_to_use": 42,
  "subtotal": 10000,
  "deduct_amount": 66,
  "used_coins": 42,
  "remaining_coins": 0,
  "tiers_used": [
    {
      "coin_amount": 5,
      "deduct_amount": 8,
      "rate": 1.6,
      "packs": 8,
      "coins": 40,
      "deduct": 64
    },
    {
      "coin_amount": 1,
      "deduct_amount": 1,
      "rate": 1,
      "packs": 2,
      "coins": 2,
      "deduct": 2
    }
  ],
  "max_deduct_percent": 11,
  "capped": false
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `coins_to_use` | int | 入参回显 |
| `subtotal` | float | 入参回显 |
| `deduct_amount` | float | **实际可抵扣金额**（前端展示这个） |
| `used_coins` | int | 实际使用的金币数（≤ coins_to_use） |
| `remaining_coins` | int | 没用完的金币数（不构成下一档最小包） |
| `tiers_used` | array | 分档明细，按 rate 降序。**触发 cap 时为空数组** |
| `tiers_used[].coin_amount` | int | 该档兑换单位 |
| `tiers_used[].deduct_amount` | float | 该档每包抵扣额 |
| `tiers_used[].rate` | float | 每金币兑换比 |
| `tiers_used[].packs` | int | 该档使用的包数 |
| `tiers_used[].coins` | int | 该档消耗的金币数 |
| `tiers_used[].deduct` | float | 该档抵扣金额 |
| `max_deduct_percent` | float | 全局比例上限 |
| `capped` | bool | 是否触发百分比上限 |

### 3.5 边界情况

| 入参 | 响应 |
|------|------|
| `coins_to_use=0` 或 `subtotal=0` | `deduct_amount=0, used_coins=0, tiers_used=[]` |
| 触发 `max_deduct_percent` 上限 | `capped=true`，`tiers_used=[]`（明细因反算不准而清空） |
| 抵扣额超过 subtotal | 截断为 subtotal |
| 用户金币余额不足 | 接口不查余额，纯展示。**前端需自己判断余额是否够** |

### 3.6 实测验证（2026-07-05）

C 端：
```bash
curl -X POST https://api.siamfeast.wenshuai.space/api/v1/coin-deduction/preview \
  -H "Authorization: Bearer <consumer_token>" \
  -H "Content-Type: application/json" \
  -d '{"coins_to_use":42,"subtotal":10000}'
# → deduct_amount: 66, used_coins: 42 ✓
```

收银端：
```bash
curl -X POST https://api.siamfeast.wenshuai.space/api/v1/cashier/coin-deduction/preview \
  -H "Authorization: Bearer <cashier_token>" \
  -H "Content-Type: application/json" \
  -d '{"coins_to_use":11,"subtotal":300}'
# → deduct_amount: 17, used_coins: 11 ✓
```

## 4. 老接口：`POST /api/v1/user-orders/calculate-coin-deduct`（已修复）

C 端 APP 已在用的老接口。原实现是硬编码 `coins × 1`（1:1 兑换），从 2026-07-05 起改为调 `PreviewCoinDeduction`，统一走 A 算法。

### 4.1 请求

```http
POST /api/v1/user-orders/calculate-coin-deduct
Authorization: Bearer <consumer_token>
Content-Type: application/json

{
  "order_amount": 10000,
  "coins_to_use": 42
}
```

### 4.2 响应

```json
{
  "coins_to_use": 42,
  "order_amount": 10000,
  "deduct_amount": 66,
  "used_coins": 42,
  "remaining_amount": 9934,
  "max_deduct_percent": 11,
  "max_deduct_amount": 1100,
  "tiers_used": [
    {"coin_amount":5,"deduct_amount":8,"rate":1.6,"packs":8,"coins":40,"deduct":64},
    {"coin_amount":1,"deduct_amount":1,"rate":1,  "packs":2,"coins":2, "deduct":2}
  ]
}
```

### 4.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `coins_to_use` | int | 入参回显 |
| `order_amount` | float | 入参回显 |
| `deduct_amount` | float | **A 算法实际抵扣金额**（前端展示这个） |
| `used_coins` | int | 实际使用的金币数 |
| `remaining_amount` | float | 剩余应付 = order_amount - deduct_amount |
| `max_deduct_percent` | float | 每单最大抵扣百分比 |
| `max_deduct_amount` | float | **本单最大可抵扣额** = order_amount × max_deduct_percent / 100 |
| `tiers_used` | array | 分档明细（调试/可选展示用） |

### 4.4 前端 UI 文案建议

- 「用 42 金币抵 ฿66」（`deduct_amount`）
- 「本单最多可抵 ฿1100」（`max_deduct_amount`）
- 「还需支付 ฿9934」（`remaining_amount`）

**不要展示任何 rate 字段**——多档位模型下没有单一 rate，展示 `1 金币 = 1.6 铢` 会误导用户（用户会以为 42 × 1.6 = 67.2，但实际是 66）。

### 4.5 与新接口 `/coin-deduction/preview` 的区别

| 维度 | `calculate-coin-deduct`（老） | `coin-deduction/preview`（新） |
|------|---|---|
| 路径 | `/api/v1/user-orders/calculate-coin-deduct` | `/api/v1/coin-deduction/preview` |
| 鉴权 | consumer | consumer |
| 入参字段名 | `order_amount`, `coins_to_use` | `subtotal`, `coins_to_use` |
| 响应字段 | 含 `remaining_amount`、`max_deduct_amount` 等「订单视角」字段 | 纯抵扣结果 + 明细 |
| 适用场景 | C 端结算页（已用） | 收银端 + 新对接场景 |

**C 端 APP 继续调老接口就行**（路径不变，响应加了字段）；**收银端 / 新对接调新接口**。

## 5. 前端集成示例

### 5.1 TypeScript

```typescript
// api/coinDeduction.ts
export interface CoinDeductionPreviewRequest {
  coins_to_use: number
  subtotal: number
}

export interface CoinTierBreakdown {
  coin_amount: number
  deduct_amount: number
  rate: number
  packs: number
  coins: number
  deduct: number
}

export interface CoinDeductionPreviewResponse {
  coins_to_use: number
  subtotal: number
  deduct_amount: number
  used_coins: number
  remaining_coins: number
  tiers_used: CoinTierBreakdown[]
  max_deduct_percent: number
  capped: boolean
}

const API_BASE = import.meta.env.VITE_API_BASE || ''

export async function previewCoinDeduction(
  token: string,
  body: CoinDeductionPreviewRequest,
  isCashier = false,
): Promise<CoinDeductionPreviewResponse> {
  const path = isCashier
    ? '/api/v1/cashier/coin-deduction/preview'
    : '/api/v1/coin-deduction/preview'
  const res = await fetch(`${API_BASE}${path}`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${token}`,
    },
    body: JSON.stringify(body),
  })
  if (!res.ok) throw new Error(`preview failed: ${res.status}`)
  return res.json()
}
```

### 5.2 Vue 3 + Composition API（结算页）

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'
import { previewCoinDeduction } from '@/api/coinDeduction'

const props = defineProps<{
  token: string
  subtotal: number
  coinsToUse: number
  isCashier?: boolean
}>()

const deductAmount = ref(0)
const usedCoins = ref(0)
const remainingCoins = ref(0)
const capped = ref(false)

watch(
  () => [props.coinsToUse, props.subtotal],
  async ([coins, subtotal]) => {
    if (!coins || !subtotal) {
      deductAmount.value = 0
      return
    }
    try {
      const r = await previewCoinDeduction(
        props.token,
        { coins_to_use: coins, subtotal },
        props.isCashier,
      )
      deductAmount.value = r.deduct_amount
      usedCoins.value = r.used_coins
      remainingCoins.value = r.remaining_coins
      capped.value = r.capped
    } catch (e) {
      console.error(e)
    }
  },
  { immediate: true },
)
</script>

<template>
  <div class="coin-preview">
    <span>金币抵扣：{{ usedCoins }} 金币 = {{ deductAmount }} 铢</span>
    <span v-if="capped" class="capped-tip">已达抵扣上限</span>
  </div>
</template>
```

### 5.3 关键约束

- **不要在前端本地算金币抵扣**，必须调本接口。本地算的算法容易和后端漂移（旧版本就是这样产生 67.2 vs 66 的差异）
- **订单详情页**：直接读后端返回的 `coin_deduct_amount` 字段（已存的就是真实值），**不要用 `coins_used × 1` 本地重算**
- 如果想给用户展示"分档明细"，直接渲染 `tiers_used` 数组

### 6.2 核心代码位置

- 算法实现：`internal/modules/marketing/deduction_config.go`
