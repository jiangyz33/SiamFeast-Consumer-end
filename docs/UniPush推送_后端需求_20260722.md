## 一、整体架构

```
APP 启动
  ↓
uni.getPushClientId() 拿 cid
  ↓
APP 上报 cid 到后端(POST /notifications/register-token)
  ↓
后端存到 user_push_tokens 表
  ↓
业务事件(订单状态变更/活动推广等)
  ↓
后端调云函数 URL(https://fc-mp-xxx.next.bspapp.com/sf-push-gateway)
  ↓
云函数调 UniPush 服务
  ↓
UniPush 通过 FCM 通道推给用户手机
  ↓
用户收到系统通知,点击跳转对应页
```

**字段说明**:

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `push_clientid` | string | ✅ | APP 上报的 cid(每个设备唯一) |
| `title` | string | ✅ | 通知栏标题 |
| `content` | string | ✅ | 通知栏内容 |
| `payload` | object | ⚠️ 可选 | 透传数据,APP 收到后用于跳转(见 § 6.1) |

### 2.3 云函数响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "errCode": 0,
    "errMsg": "success"
  }
}
```

错误码:

| code | 说明 |
|---|---|
| 0 | 成功 |
| `PUSH_CLIENT_ID_REQUIRED` | 缺 push_clientid |
| `PUSH_CONTENT_REQUIRED` | 缺 title/content |
| `PUSH_SEND_FAILED` | UniPush 服务发送失败 |

## 三、需要后端做的事

### 3.1 数据库新建表

#### `user_push_tokens`(用户推送 token)

```sql
CREATE TABLE user_push_tokens (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token VARCHAR(128) NOT NULL,        -- UniPush cid
  platform VARCHAR(16) NOT NULL,      -- 'unipush'(预留 'ios_apns')
  device_info TEXT,                   -- APP 上报的设备信息
  app_version VARCHAR(32),
  last_active_at TIMESTAMP DEFAULT NOW(),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, token)
);

CREATE INDEX idx_push_tokens_user ON user_push_tokens(user_id);
CREATE INDEX idx_push_tokens_token ON user_push_tokens(token);
```

#### `notifications`(消息历史,可选但推荐)

```sql
CREATE TABLE notifications (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT REFERENCES users(id) ON DELETE CASCADE,
  type VARCHAR(32) NOT NULL,          -- 'order' / 'coupon' / 'activity' / 'system'
  title VARCHAR(128),
  content TEXT,
  payload JSONB,
  is_read BOOLEAN DEFAULT FALSE,
  push_status VARCHAR(16),            -- 'pending' / 'sent' / 'failed'
  pushed_at TIMESTAMP,
  read_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_notifications_user_unread ON notifications(user_id, is_read);
```

### 3.2 新增 4 个接口

#### 接口 1:`POST /api/v1/notifications/register-token`(APP 调用)

**用途**:APP 启动后/登录后上报 push cid,关联到当前用户。

**请求**:
```http
POST /api/v1/notifications/register-token
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "token": "c8e3a2b5f4xxxxxxxxxxxxxxxxx",
  "platform": "unipush",
  "device_info": "Xiaomi/Redmi K30/Android 12",
  "app_version": "1.0.9"
}
```

**后端处理**:
```sql
-- UPSERT:已存在则更新 last_active_at,不存在则 INSERT
INSERT INTO user_push_tokens (user_id, token, platform, device_info, app_version, last_active_at)
VALUES (:current_user_id, :token, :platform, :device_info, :app_version, NOW())
ON CONFLICT (user_id, token)
DO UPDATE SET
  last_active_at = NOW(),
  device_info = EXCLUDED.device_info,
  app_version = EXCLUDED.app_version;
```

**响应**:
```json
{
  "code": 0,
  "message": "success"
}
```

**错误码**:

| HTTP | code | 场景 |
|---|---|---|
| 401 | `UNAUTHENTICATED` | 未登录 |
| 400 | `TOKEN_REQUIRED` | 缺 token 字段 |

#### 接口 2:`POST /api/v1/notifications/unregister-token`(APP 调用)

**用途**:用户退出登录时,清掉当前设备的 cid 关联(避免注销后还收到推送)。

```http
}
```

**后端处理**:
```sql
DELETE FROM user_push_tokens
```

**响应**:

```json
}
```

### 3.3 实现 PushService(后端核心)

#### 工具函数签名

```go
// Go 示例
type PushService struct {
    cloudFuncURL string  // 云函数 URL
    httpClient   *http.Client
}

type PushMessage struct {
    Title   string                 // 通知标题
    Body    string                 // 通知内容
    Type    string                 // 'order' / 'coupon' / 'activity' / 'system'
    Payload map[string]interface{} // 透传数据
}

// 推送给单个用户(所有设备)
func (s *PushService) Send(ctx context.Context, userID int64, msg PushMessage) error {
    // 1. 查该用户所有 push token
    tokens := db.QueryPushTokens(userID)
    if len(tokens) == 0 {
        return nil  // 用户没设备,跳过
    }

    // 2. 创建 notifications 记录(存消息历史)
    notifID := db.InsertNotification(userID, msg.Type, msg.Title, msg.Body, msg.Payload)

    // 3. 对每个 token 调云函数
    for _, token := range tokens {
        err := s.callCloudFunction(token, msg)
        if err != nil {
            log.Errorf("push failed: user=%d token=%s err=%v", userID, token, err)
        }
    }

    // 4. 更新 notifications 状态
    db.UpdatePushStatus(notifID, "sent")

    return nil
}

// 调云函数
func (s *PushService) callCloudFunction(cid string, msg PushMessage) error {
    body := map[string]interface{}{
        "push_clientid": cid,
        "title":         msg.Title,
        "content":       msg.Body,
        "payload":       mergeType(msg),
    }
    jsonBody, _ := json.Marshal(body)

    resp, err := s.httpClient.Post(s.cloudFuncURL, "application/json", bytes.NewReader(jsonBody))
    if err != nil {
        return err
    }
    defer resp.Body.Close()

    // 解析云函数返回
    var result struct {
        Code    int    `json:"code"`
        Message string `json:"message"`
    }
    json.NewDecoder(resp.Body).Decode(&result)

    if result.Code != 0 {
        return fmt.Errorf("cloud func error: %s", result.Message)
    }
    return nil
}

// 把 type 字段塞到 payload 里(前端根据 payload.type 跳转)
func mergeType(msg PushMessage) map[string]interface{} {
    p := msg.Payload
    if p == nil {
        p = map[string]interface{}{}
    }
    p["type"] = msg.Type
    return p
}
```

### 6.1 APP 收到推送后的跳转规则

前端 `utils/push.js` 根据 `payload.type` 跳转:

| payload.type | 含义 | 跳转目标 |
|---|---|---|
| `order` | 订单相关 | `payload.order_id` → `/pages/order-detail/index?id=xxx` |
| `coupon` | 优惠券相关 | `/pages/coupons/index` |
| `activity` / `campaign` | 活动相关 | `/pages/banner-detail/index?id=xxx` |
| `system` 或 无 type | 系统消息/默认 | `/pages/index/index` |

## 九、常见问题

### Q1:cid 从哪里拿?

APP 端启动后,`utils/push.js` 调 `uni.getPushClientId()` 自动拿到 cid。然后上报到 `/notifications/register-token`。

后端不用主动拿 cid,从前端的 POST 请求体里取。

### Q2:同一用户多设备怎么处理?

`user_push_tokens` 表 `(user_id, token)` 联合唯一,允许同一用户关联多个设备。推送时遍历所有设备 token 都推一遍。

### Q3:cid 会变吗?

会。用户**卸载重装 APP / 清数据** 时,cid 会变。前端在 APP 启动时自动上报,后端 UPSERT 即可。

### Q4:云函数 URL 会变吗?

不会。一旦部署,URL 固定。除非后端在 uniCloud Web 控制台手动改。

### Q5:推送给离线用户,消息会丢吗?

不会。UniPush + FCM 会缓存(默认 30 天),用户上线后投递。

### Q6:推送费用?

- UniPush 基础服务:**免费**
- FCM:**完全免费**
- 云函数调用:每月 10 万次免费(支付宝云)
- 小应用(<10 万用户)**完全免费**

### Q7:如何避免骚扰用户?

后端频率限制:

| 限制 | 阈值 |
|---|---|
| 单用户每小时 | ≤ 5 条 |
| 单用户每天 | ≤ 20 条 |
| 广播频率 | ≤ 每天 1 次 |

### Q8:泰国用户手机没 Google Play 怎么办?

UniPush 自动检测:
- 有 Google Play → 走 FCM
- 没有 → 走厂商通道(华为/小米/OPPO/vivo)

泰国本地用户手机基本都装了 Google Play,走 FCM 稳定。

### Q9:推送送达率?

- FCM 通道:> 95%
- 在线消息(APP 打开):100%
- 离线消息:几秒到几十秒到达

### Q10:用户关掉通知权限怎么办?

推送依然会到达 APP(但不在通知栏显示),APP 打开后可以从 `/notifications` 接口拉历史消息。
