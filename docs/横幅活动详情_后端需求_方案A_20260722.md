## 一、方案说明

### 1.1 业务流程

```
admin-web 创建活动(campaigns 表)
    ↓
admin-web 创建/编辑横幅时,绑定某个 campaign
    ↓ banners.campaign_id = campaigns.id
C 端首页 GET /banners
    ↓ 返回 banner + 内嵌 campaign 详情
用户点击横幅
    ↓
弹出"活动详情弹窗"(根据 campaign.type 显示不同 UI)
    ↓
    ├─ DISCOUNT/FULL_REDUCTION:纯展示 + "立即下单"按钮
    └─ COUPON_GRANT:可领优惠券列表 + "立即抢券"按钮
```

### 1.2 为什么选方案 A

| 对比 | 方案 A(横幅绑定) | 方案 B(独立活动页)|
|---|---|---|
| 用户路径 | 首页→点横幅→看活动 | 首页→点横幅→活动列表→活动详情 |
| 转化率 | 高(1 步)| 低(2 步)|
| 后端工作量 | 小(加 1 字段 + 1 接口)| 中(加 2 接口)|
| 前端工作量 | 中(改造弹窗)| 大(新建 2 个页面)|

### 1.3 与工单差异

工单是**完整活动中心**(列表页 + 详情页),方案 A 是**轻量版**:
- ❌ 不做活动列表页(横幅本身就是入口)
- ✅ 活动详情弹窗(集成到首页横幅弹窗)
- ✅ 抢券功能(完整保留)

### 3.2 `GET /api/v1/user/campaigns/:id/claimable-coupons`(新增)

**用途**:活动详情弹窗(COUPON_GRANT 类型)展示"可领优惠券列表"。

**请求**:
```http
GET /api/v1/user/campaigns/25/claimable-coupons
Authorization: Bearer <token>
```

**响应**:
```json
{
  "code": 0,
  "data": {
    "campaign_id": 25,
    "coupons": [
      {
        "id": 15,
        "template_id": 15,
        "name": "满 200 减 30",
        "name_en": "$30 off $200+",
        "name_th": "ลด 30 เมื่อซื้อครบ 200",
        "coupon_type": "FULL_REDUCTION",
        "discount_value": 30,
        "min_amount": 200,
        "total_quantity": 200,
        "claimed_count": 113,
        "remaining": 87,
        "user_claimed": false,
        "user_can_claim": true
      },
      {
        "id": 16,
        "template_id": 16,
        "name": "满 500 减 100",
        "coupon_type": "FULL_REDUCTION",
        "discount_value": 100,
        "min_amount": 500,
        "total_quantity": 100,
        "claimed_count": 100,
        "remaining": 0,
        "user_claimed": false,
        "user_can_claim": false
      }
    ]
  }
}
```

**字段说明**:

| 字段 | 类型 | 说明 |
|---|---|---|
| `template_id` | int | 优惠券模板 ID(抢券接口用) |
| `coupon_type` | string | `FIXED`(固定金额)/ `PERCENTAGE`(折扣)/ `FULL_REDUCTION`(满减) |
| `discount_value` | number | 折扣值(金额或百分比) |
| `min_amount` | number | 使用门槛(满多少可用) |
| `total_quantity` | int | 活动期总量 |
| `claimed_count` | int | 已领取数 |
| `remaining` | int | 剩余数(total - claimed) |
| `user_claimed` | bool | 当前用户**是否已领过** |
| `user_can_claim` | bool | 当前用户**现在能否领**(综合判断:user_claimed + per_user_limit + daily_limit + remaining) |

**后端实现要点**:

1. **查 campaign.rules.coupon_template_ids**(JSONB 数组)
2. **批量查 templates**:用 `IN (...)` 查 `coupon_templates` 表
3. **批量查 claimed_count**:`SELECT template_id, COUNT(*) FROM user_coupons WHERE template_id IN (...) GROUP BY template_id`
4. **批量查 user_claimed**:`SELECT template_id FROM user_coupons WHERE user_id = ? AND template_id IN (...)`
5. **综合判断 user_can_claim**:
   ```
   user_can_claim =
     !user_claimed
     && remaining > 0
     && claimed_today < daily_limit
     && claimed_total < per_user_limit
   ```

```json
    "coupon_name": "满 200 减 30"
  }

```

**错误码**(前端按这些做不同 UI):

| HTTP | code | 场景 | 前端文案 |
|---|---|---|---|
| 200 | 0 | 成功 | "领取成功" |
| 400 | `COUPON_SOLD_OUT` | 已抢光 | "已抢光" |
| 400 | `DAILY_QUOTA_EXCEEDED` | 当日发放总量用尽 | "今日已领完,明天再来" |
| 400 | `CLAIM_LIMIT_REACHED` | 用户超过 per_user_limit | "您已领过此券" |
| 400 | `DAILY_LIMIT_REACHED` | 用户超过 daily_limit | "今日领取已达上限" |
| 400 | `COUPON_INACTIVE` | 活动未开始/已结束 | "活动未开始/已结束" |
| 401 | `UNAUTHENTICATED` | 未登录 | "请先登录" |

## 四、前端使用接口的方式

### 4.1 首页横幅数据流

```javascript
// 1. 进入首页,拉横幅
GET /banners
  ↓ 返回 banners[],每个 banner 可能有内嵌 campaign

// 2. 渲染横幅 swiper
this.banners = res.data.items

// 3. 用户点击横幅
handleBannerClick(banner) {
  if (banner.campaign_id && banner.campaign) {
    // 有活动 → 弹活动详情弹窗
    this.openCampaignModal(banner.campaign)
  } else if (banner.detail_images?.length > 0) {
    // 有详情图 → 弹图片弹窗(现有逻辑)
    this.openImageModal(banner.detail_images)
  } else if (banner.link_type) {
    // 有链接 → 跳转(现有逻辑)
    this.navigateByLinkType(banner.link_type, banner.link_value)
  }
}
```

### 4.2 活动详情弹窗(COUPON_GRANT 类型)

```javascript
// 打开弹窗时,如果是 COUPON_GRANT,拉可领优惠券
async openCampaignModal(campaign) {
  this.currentCampaign = campaign
  this.showCampaignModal = true

  if (campaign.type === 'COUPON_GRANT') {
    const res = await getCampaignClaimableCoupons(campaign.id)
    this.claimableCoupons = res.data.coupons
  }
}

// 用户点"立即抢券"
async handleClaimCoupon(templateId) {
  try {
    await claimCoupon(templateId)
    // 成功:更新本地状态(按钮变"已领取")
    this.updateCouponClaimedStatus(templateId)
  } catch (e) {
    // 失败:按错误码提示
    showToast(resolveClaimError(e.code))
  }
}
```

## 十一、常见问题

### Q1:banners 表已经有 link_type / link_value,加了 campaign_id 后这三者关系?

**优先级**(前端处理):
```
1. campaign_id 不空 → 弹活动详情弹窗
2. detail_images 不空 → 弹图片弹窗
3. link_type 不空 → 跳转
4. 都没有 → 无操作
```

三者**互斥**,admin-web 编辑横幅时建议根据是否选活动,动态显示/隐藏 link_type 字段。

### Q2:campaigns 表的 status 字段

后端在 `/banners` 内嵌 campaign 时,应过滤:
- 只返回 `status = 'ACTIVE'`
- 且 `start_date <= NOW() <= end_date`

否则 campaign_id 有值但 campaign 应返回 `null`。

### Q3:抢券失败时,前端怎么知道 4 种错误?

后端 `/user/coupons/claim` 返回错误码(见 § 3.3),前端按 code 显示文案。

### Q4:多语言怎么处理?

后端 campaign 同时返回 `name / name_en / name_th`,前端按 locale 选。如果某语言字段为空,fallback 到 `name`(中文)。

### Q5:管理员手动改 banners.campaign_id 行不行?

可以。admin-web 编辑界面没做的话,直接 SQL 改:
```sql
UPDATE banners SET campaign_id = 22 WHERE id = 101;
```
