# 2026-05-10 C端APP优惠专区接口说明文档

## 1. 功能定位

C 端 APP 优惠专区用于展示所有门店的优惠菜品集合。

本接口不读取拼团商品，不读取优惠券，不读取活动表。

数据来源：

```text
menu_items
```

优惠判断规则：

```sql
menu_items.original_price IS NOT NULL
AND menu_items.original_price > menu_items.price
```

也就是说：

```text
original_price = 原价/划线价
price = 当前售价/优惠价
original_price > price = 优惠菜品
```

## 2. 接口列表

| 场景 | 接口 | 说明 |
|---|---|---|
| 优惠专区列表 | `GET /api/v1/public/discount-menu-items` | 未登录也可访问 |
| 优惠专区列表 | `GET /api/v1/discount-menu-items` | 登录用户访问 |
| 菜品详情 | `GET /api/v1/public/menu-items/{id}` | 点击优惠菜品进入详情 |
| 菜品规格/口味/加料 | `GET /api/v1/public/menu-items/{id}/options` | 详情页选择规格使用 |
| 下单 | `POST /api/v1/user-orders` | 登录后普通订单下单 |

## 3. 优惠专区列表接口

### 3.1 请求地址

```http
GET /api/v1/public/discount-menu-items
```

登录用户也可以调用：

```http
GET /api/v1/discount-menu-items
```

### 3.2 是否需要登录

| 接口 | 是否需要登录 |
|---|---:|
| `/api/v1/public/discount-menu-items` | 否 |
| `/api/v1/discount-menu-items` | 是 |

APP 首页、优惠专区入口建议优先使用公开接口。

## 4. 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `page` | int | 否 | 1 | 页码 |
| `page_size` | int | 否 | 20 | 每页数量 |
| `category_id` | int64 | 否 | - | 全局菜品分类 ID |
| `keyword` | string | 否 | - | 菜品名称模糊搜索，支持中英泰名称 |
| `store_id` | int64 | 否 | - | 指定门店 |
| `business_type` | string | 否 | - | 经营品类 |
| `lat` | float | 否 | - | 用户纬度 |
| `lng` | float | 否 | - | 用户经度 |
| `sort` | string | 否 | default | 排序方式 |

### 4.1 `sort` 可选值

| 值 | 说明 |
|---|---|
| 空 / `default` | 默认排序：菜品排序值 + 创建时间倒序 |
| `distance` | 按距离从近到远，需要同时传 `lat`、`lng` |
| `discount` | 按折扣力度排序，折扣越低越靠前 |
| `price_asc` | 按优惠价从低到高 |
| `price_desc` | 按优惠价从高到低 |

## 5. APP 分页建议

APP 必须使用分页，不建议一次性拉全量。

首屏：

```http
GET /api/v1/public/discount-menu-items?page=1&page_size=20
```

上拉加载更多：

```http
GET /api/v1/public/discount-menu-items?page=2&page_size=20
```

推荐 APP 端逻辑：

```text
1. 首次进入优惠专区，请求 page=1&page_size=20
2. 下拉刷新时，重新请求 page=1
3. 上拉加载时，page + 1
4. 当 page >= total_pages 时停止加载
5. 如果 items 为空，展示空状态
```

是否还有下一页：

```text
has_more = page < total_pages
```

## 6. 请求示例

### 6.1 查询全部优惠菜品

```http
GET /api/v1/public/discount-menu-items?page=1&page_size=20
```

### 6.2 按全局菜品分类筛选

```http
GET /api/v1/public/discount-menu-items?category_id=12&page=1&page_size=20
```

### 6.3 按菜名搜索

```http
GET /api/v1/public/discount-menu-items?keyword=牛肉&page=1&page_size=20
```

### 6.4 按距离排序

```http
GET /api/v1/public/discount-menu-items?lat=13.7563&lng=100.5018&sort=distance&page=1&page_size=20
```

### 6.5 按门店筛选

```http
GET /api/v1/public/discount-menu-items?store_id=1&page=1&page_size=20
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `original_price` | number | 原价/划线价 |

| `discount_amount` | number | 优惠金额，`original_price - discount_price` |
| `discount_rate` | number | 折扣比例，`discount_price / original_price` |

APP 展示建议：

```text

现价：discount_price，高亮展示
折扣：discount_rate，可转成 6.7 折之类的展示
```

## 10. 菜品规格接口

如果详情返回：

```json
{
  "has_options": true,
  "options_api": "/api/v1/public/menu-items/88/options"
}
```

APP 再请求：

```http
GET /api/v1/public/menu-items/88/options?store_id=1
```

说明：

| 字段 | 说明 |
|---|---|
| `specs` | 规格，例如大份、小份 |
| `flavors` | 口味，例如少辣、不辣 |
| `toppings` | 加料，例如肥牛、虾滑 |
| `combos` | 套餐组合 |

## 11. 下单链路

优惠专区菜品是普通菜品，走普通 C 端订单。

接口：

```http
POST /api/v1/user-orders
```

请求示例：

```json
{
  "store_id": 1,
  "order_type": "DELIVERY",
  "items": [
    {
      "menu_item_id": 88,
      "quantity": 1,
      "selection": {
        "spec_id": 2,
        "flavor_id": 4,
        "topping_ids": [8],
        "remark": "少盐"
      }
    }
  ]
}
```

价格计算：

```text
最终单价 = menu_items.price + 规格加价 + 口味加价 + 加料价格
```

其中：

```text
menu_items.price 已经是优惠价
```

## 12. 和拼团专区的区别

| 对比项 | 优惠专区 | 拼团专区 |
|---|---|---|
| 数据来源 | `menu_items` | `group_buy_items` |
| 是否读取拼团 | 否 | 是 |
| 价格字段 | `original_price` / `price` | `original_price` / `group_price` |
| 是否能进购物车 | 可以 |
| 是否能混买 | 可以 |
| 是否有库存限购 | 不做 |
| 下单接口 | 普通订单 `POST /user-orders` | 拼团订单接口 |
| 是否可选规格口味 | 可以，走普通菜品规格 |

## 14. 错误返回

### 14.1 参数错误

```json
{
  "code": "INVALID_PARAM",
  "message": "无效的 category_id"
}
```

### 14.2 菜品不存在或不可售

```json
{
  "code": "NOT_FOUND",
  "message": "资源不存在"
}
```

## 15. 前端接入顺序

建议按这个顺序接：

1. 接 `/api/v1/public/discount-menu-items`，完成优惠专区列表。
2. 接分页加载，使用 `page < total_pages` 判断是否还有更多。
3. 接 `category_id` 筛选，分类数据复用 `/api/v1/public/categories`。
4. 接 `keyword` 搜索。
5. 点击菜品后接 `/api/v1/public/menu-items/{id}`。
6. 如果 `has_options=true`，接 `/api/v1/public/menu-items/{id}/options?store_id={store_id}`。
7. 最后接普通下单 `/api/v1/user-orders`。

## 16. 验收标准

| 验收项 | 标准 |
|---|---|
| 优惠数据来源正确 | 只查询 `menu_items.original_price > menu_items.price` |
| 不混入拼团 | 不读取 `group_buy_items` |
| 每个菜品带门店 | 返回 `store_id`、`store_name` |
| 支持 APP 分页 | 返回 `page`、`page_size`、`total`、`total_pages` |
| 支持分类筛选 | `category_id` 生效 |
| 支持菜名搜索 | `keyword` 生效 |
| 支持点击详情 | 返回 `menu_item_id` 和 `detail_api` |
| 详情可展示门店 | 详情接口返回门店名称 |
| 下单链路正确 | 走普通订单接口 |
