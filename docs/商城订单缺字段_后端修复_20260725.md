# 商城订单接口缺少 store_id / pickup_time 字段

> 日期:2026-07-25
> 收件人:后端
> 发件人:前端 jiangyz33
> 优先级:P0(影响 C 端订单详情显示)
> 关联修复:`2026-07-25_商城兑换门店校验修复报告.md`

---

## 一、问题现象

C 端兑换商品时,前端**已传** `store_id` 和 `pickup_time`,后端**已接收并创建订单**。

但 `GET /api/v1/mall/my-orders` 返回的订单数据里**没有**这两个字段:

```json
{
  "items": [{
    "id": 51,
    "user_id": 105,
    "product_id": 5,
    "product_name": "咖啡兑换卷",
    "exchange_type": "POINT",
    "coin_cost": 50,
    "quantity": 1,
    "status": "PENDING",
    "unique_code": "c99a204d-...",
    "recipient_name": null,
    "recipient_phone": null,
    "recipient_address": null,
    "shipping_n...
    // ❌ 缺少 store_id
    // ❌ 缺少 pickup_time
    // ❌ 缺少 store_name
  }]
}
```

---

## 二、前端已确认传了参数

兑换请求日志(来自 C 端控制台):

```
[exchange] request: {
  "product_id": 5,
  "exchange_type": "points",
  "quantity": 1,
  "store_id": 55,
  "pickup_time": "2026-07-27T09:00:00+07:00",
  "points_amount": 50
}
```

后端返回 `code: 0`,订单创建成功。说明 `store_id=55` 和 `pickup_time` **已经写入了 mall_orders 表**。

但查询时不返回。

---

## 三、需要后端修复

### 3.1 修改 `GET /api/v1/mall/my-orders`

**文件**: `internal/modules/mall/repository.go` 的 `ListUserOrders` 方法

**当前 SQL**(推测):

```sql
SELECT id, user_id, product_id, product_name, product_name_en, product_name_th,
       product_image, exchange_type, coin_cost, quantity, status, unique_code,
       recipient_name, recipient_phone, recipient_address, ...
FROM mall_orders
WHERE user_id = $1
ORDER BY created_at DESC
LIMIT $2 OFFSET $3
```

**改成**(加 store_id + pickup_time + JOIN stores):

```sql
SELECT m.id, m.user_id, m.product_id, m.product_name, m.product_name_en, m.product_name_th,
       m.product_image, m.exchange_type, m.coin_cost, m.quantity, m.status, m.unique_code,
       m.recipient_name, m.recipient_phone, m.recipient_address,
       m.store_id,
       m.pickup_time,
       m.notify_status,
       s.name AS store_name,
       s.name_en AS store_name_en,
       s.name_th AS store_name_th
FROM mall_orders m
LEFT JOIN stores s ON m.store_id = s.id
WHERE m.user_id = $1
ORDER BY m.created_at DESC
LIMIT $2 OFFSET $3
```

### 3.2 修改 `GET /api/v1/mall/my-orders/:id`(单个订单详情)

同样加 `store_id` + `pickup_time` + JOIN stores。

### 3.3 Model/DTO 加字段

**文件**: `internal/model/mall_order.go` 或 `internal/dto/response/mall.go`

```go
type MallOrderResponse struct {
    // ... 原有字段 ...
    StoreID      *int64     `json:"store_id"`
    PickupTime   *time.Time `json:"pickup_time"`
    NotifyStatus string     `json:"notify_status"`
    StoreName    string     `json:"store_name,omitempty"`
    StoreNameEn  string     `json:"store_name_en,omitempty"`
    StoreNameTh  string     `json:"store_name_th,omitempty"`
}
```

### 3.4 验证字段确实存在

```sql
-- 确认 mall_orders 表有 store_id / pickup_time 列
\d mall_orders

-- 查看刚兑换的订单数据
SELECT id, store_id, pickup_time FROM mall_orders WHERE id = 51;
```

预期输出:
```
 id | store_id |      pickup_time
----+----------+------------------------
 51 |       55 | 2026-07-27T09:00:00+07
```

如果 `store_id` 或 `pickup_time` 是 NULL,说明兑换时**没写入**(那是另一个 bug)。
