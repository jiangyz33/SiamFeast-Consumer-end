# 订单接口补充"可获得金币/积分"字段 — 后端工单

> 日期：2026-08-06
> 发件人：前端 jiangyz33
> 收件人：后端
> 优先级：P2（提升用户体验，让用户下单前知道能获得多少金币/积分）
> 关联接口：
> - `POST /api/v1/orders/preview`（结算页预览）
> - `GET /api/v1/user-orders/:id`（订单详情）
> - `GET /api/v1/user-orders/my-orders`（订单列表，可选）

---

## 1. 背景

当前用户在下单流程中**看不到订单能获得多少金币和积分**。用户期望：

- **结算页（preview）**：显示"本订单预计获得 X 金币 / Y 积分"
- **订单详情页**：显示该订单**实际获得**的金币和积分数

## 2. 当前接口字段现状

### 2.1 `POST /orders/preview` 响应（已返回但缺字段）

```json
{
  "subtotal": 10000,
  "campaign_discount": 1000,
  "coupon_discount": 0,
  "coin_deduct": 0,
  "total_amount": 9000,
  "discount_eligible": true
}
```

**缺失**：无"预计获得金币/积分"字段。

### 2.2 `GET /user-orders/:id` 响应

```json
{
  "order": {
    "id": 584,
    "total_amount": 9000,
    "coin_deduct_amount": 0,
    "coins_used": 0,
    "status": "COMPLETED"
  },
  "items": [...]
}
```

**缺失**：无"实际获得金币/积分"字段。

---

## 3. 需求

### 3.1 `POST /orders/preview` 新增字段

```json
{
  "subtotal": 10000,
  "total_amount": 9000,
  "expected_coins": 90,        // ← 新增：本订单预计获得金币数
  "expected_points": 90,       // ← 新增：本订单预计获得积分数
  "expected_coins_breakdown": { // ← 可选：金币明细（让前端展示来源）
    "base": 90,                 //   基础获得（按消费额 × 比例）
    "campaign_bonus": 0,        //   活动加赠（如开业 extra_coins）
    "total": 90
  },
  "expected_points_breakdown": { // ← 可选：积分明细
    "base": 90,
    "campaign_bonus": 0,         //   活动加赠（如开业 extra_points）
    "total": 90
  }
}
```

### 3.2 `GET /user-orders/:id` 新增字段（order 对象内）

```json
{
  "order": {
    "id": 584,
    "total_amount": 9000,
    "coins_earned": 90,         // ← 新增：该订单实际获得的金币数
    "points_earned": 90,        // ← 新增：该订单实际获得的积分数
    "coins_earned_at": "2026-08-04T...",  // ← 可选：金币发放时间
    "points_earned_at": "2026-08-04T..."  // ← 可选：积分发放时间
  }
}
```

### 3.3 `GET /user-orders/my-orders` 订单列表（可选）

每条订单摘要里也加 `coins_earned` / `points_earned`（方便列表页直接展示）。

---

## 4. 计算规则说明（供后端参考）

### 4.1 预计金币（preview）

```
expected_coins = floor(total_amount × coin_earn_rate) + campaign_bonus_coins

其中：
- coin_earn_rate：消费返金币比例（全局配置，如 1% = 消费 100 铢返 1 金币）
- campaign_bonus_coins：活动加赠（如开业活动 extra_coins、特殊日期 extra_coins）
- 如果 discount_eligible=false（纯酒水订单），可能不返金币 → 返回 0
```

### 4.2 预计积分（preview）

```
expected_points = floor(total_amount × point_earn_rate) + campaign_bonus_points

同理：
- point_earn_rate：消费返积分比例
- campaign_bonus_points：活动加赠
```

### 4.3 实际获得（order detail）

- 订单完成（COMPLETED）后**已发放**的金币/积分数
- 如果订单被取消（CANCELLED）→ 应为 0 或 null
- 如果订单待支付（PENDING_PAYMENT）→ 应为 0 或 null（未发放）

## 6. 字段命名约定

| 字段 | 类型 | 说明 |
|---|---|---|
| `expected_coins` | int | 预计获得金币数（preview） |
| `expected_points` | int | 预计获得积分数（preview） |
| `expected_coins_breakdown` | object\|null | 金币明细（可选） |
| `expected_points_breakdown` | object\|null | 积分明细（可选） |
| `coins_earned` | int | 实际获得金币（order detail） |
| `points_earned` | int | 实际获得积分（order detail） |

---

## 7. 兼容性

- 老版本前端：忽略新字段，不影响现有行为
- 新字段为 0 或 null 时：前端不展示该行
- 订单未完成时：`coins_earned` / `points_earned` 返回 0 或 null

---

## 8. 验证用例

| 场景 | expected_coins | expected_points | 说明 |
|---|---|---|---|
| 普通订单 ฿9,000（1% 返利）| 90 | 90 | 基础返利 |
| 开业活动期（extra_coins=10, extra_points=50）| 100 | 140 | 基础 + 活动加赠 |
| 纯酒水订单（discount_eligible=false）| 0 | 0 | 不返利 |
| 金币抵扣后 total=฿8,000 | 80 | 80 | 按实付金额算 |
