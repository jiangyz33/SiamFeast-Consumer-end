# 拼团功能（GroupBuy）说明文档

> 版本：v1.0 / 2026-05-10

---

## 1. 功能概述

拼团单品直购模块，门店将菜品以优惠价发起拼团活动，消费者直接购买（无购物车），一口价快速下单。

**核心流程**：门店创建拼团商品 → 消费者浏览/下单 → 支付 → 完成；取消订单时自动释放库存。

**设计原则**：
- 独立路径，不与普通下单流程混合
- 无购物车、无优惠券、无拼团间互斥
- `quantity` 由消费者指定，受 `max_per_user` 约束

## 2. 数据库

### 2.1 表结构

迁移文件：`migrations/000052_group_buy_items.up.sql`

```sql
CREATE TABLE group_buy_items (
    id              BIGSERIAL PRIMARY KEY,
    store_id        BIGINT NOT NULL,          -- 所属门店
    menu_item_id    BIGINT NOT NULL,          -- 关联菜品

    original_price  NUMERIC(10,2) NOT NULL,   -- 原价（自动从 menu_items 读取）
    group_price     NUMERIC(10,2) NOT NULL,   -- 拼团价（必须 < 原价）
    discount_rate   NUMERIC(5,2)  NOT NULL DEFAULT 1.00,  -- 折扣率 = group_price / original_price

    total_quota     INT NOT NULL DEFAULT 0,   -- 总库存
    sold_count      INT NOT NULL DEFAULT 0,   -- 已售数量
    max_per_user    INT NOT NULL DEFAULT 1,   -- 每人限购

    start_at        TIMESTAMPTZ NOT NULL,     -- 活动开始时间
    end_at          TIMESTAMPTZ NOT NULL,     -- 活动结束时间

    share_code      VARCHAR(64) NOT NULL UNIQUE,  -- 分享码（系统自动生成）
    is_active       BOOLEAN NOT NULL DEFAULT TRUE, -- 是否上架
    sort_order      INT NOT NULL DEFAULT 0,       -- 排序权重

    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 2.2 索引

| 索引 | 用途 |
|------|------|
| `idx_gbi_store` | 按门店查询 |
| `idx_gbi_menu_item` | 按菜品查询（重叠检测） |
| `idx_gbi_active_time` | C端在售商品筛选 |
| `idx_gbi_share_code` | 分享码查询（UNIQUE） |

### 2.3 与 orders 表的关系

拼团订单写入现有 `orders` 表：

| 字段 | 拼团订单值 |
|------|-----------|
| `order_type` | `GROUP_BUY` |
| `order_source` | `GROUP_BUY` |
| `order_no` | `GB` + 时间戳 + 商品ID |
| `extra_data` | `{order_mode, group_buy_item_id, menu_item_id, original_price, group_price, discount_amount}` |

`order_items.specs`：

```json
{"original_price": 97, "group_price": 59.9, "group_buy_item_id": 1, "quantity": 2}
```

## 3. API 接口

### 3.1 门店端（ops-api :8080）

需要 `store_admin` / `cashier` 角色 + 门店 scope。

---

#### 3.1.1 创建拼团商品

```
POST /api/v1/group-buy/items
Content-Type: application/json
Authorization: Bearer <store_admin_token>
```

请求体：

```json
{
    "menu_item_id": 3007,
    "group_price": 59.9,
    "total_quota": 100,
    "max_per_user": 2,
    "start_at": "2026-05-01T00:00:00Z",
    "end_at": "2026-12-31T23:59:59Z",
    "sort_order": 1
}
```

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| menu_item_id | int64 | 是 | 必须属于当前门店 |
| group_price | float64 | 是 | > 0 且 < 菜品原价 |
| total_quota | int | 是 | > 0 |
| max_per_user | int | 是 | >= 1 |
| start_at | datetime | 是 | ISO 8601 |
| end_at | datetime | 是 | 必须晚于 start_at |
| sort_order | int | 否 | 默认 0 |

成功 `201`：

```json
{"id": 1, "message": "created"}
```

业务规则：
- `original_price` 从 `menu_items.price` 自动读取
- `discount_rate` 自动计算：`group_price / original_price`
- `share_code` 自动生成，格式 `GB` + YYYYMMDD + 门店ID后3位 + 4位序号
- 同一门店同一菜品不允许时间段重叠

## 4. 业务逻辑

### 4.1 创建拼团商品校验链

```
结束时间 > 开始时间
  → 菜品存在且属于当前门店（读 menu_items.price 作为原价）
    → 拼团价 > 0 且 < 原价
      → 同门店同菜品无时间段重叠
        → 生成唯一 share_code
          → 自动计算 discount_rate
            → 写入
```

### 4.2 下单事务（SELECT FOR UPDATE）

```
BEGIN TX (ReadCommitted)
  1. SELECT ... FOR UPDATE        ← 行锁拼团商品
  2. 校验 is_active / 时间 / 库存 / 限购 / 菜品上架
  3. UPDATE sold_count += quantity ← 扣库存
  4. INSERT orders                ← order_type='GROUP_BUY'
  5. INSERT order_items           ← specs 存拼团元数据
COMMIT
```

**每人限购**：统计用户所有非取消订单中 `order_items.specs->>'group_buy_item_id'` 匹配的 quantity 之和。

### 4.3 取消订单释放库存

取消拼团订单时自动：
1. 读 `order_items.specs` 中的 `group_buy_item_id` + `quantity`
2. `UPDATE group_buy_items SET sold_count = GREATEST(sold_count - quantity, 0)`

非拼团订单不受影响（specs 中无 `group_buy_item_id` 则跳过）。

### 4.4 分享码规则

```
GB + YYYYMMDD + 门店ID后3位 + 4位顺序号
例：GB202605090010001
```

## 5. 错误码

| HTTP | Code | Message | 场景 |
|------|------|---------|------|
| 400 | `GROUP_BUY_INVALID_TIME_RANGE` | 结束时间必须晚于开始时间 | 创建 |
| 400 | `GROUP_BUY_PRICE_INVALID` | 拼团价必须大于 0 且小于原价 X | 创建/更新 |
| 400 | `GROUP_BUY_QUOTA_INVALID` | 总库存不能小于已售数量 X | 更新库存 |
| 404 | `GROUP_BUY_NOT_FOUND` | 拼团商品不存在 | 查询/更新/删除 |
| 404 | `GROUP_BUY_MENU_ITEM_NOT_FOUND` | 菜品不存在或不属于当前门店 | 创建 |
| 409 | `GROUP_BUY_TIME_OVERLAP` | 该菜品在指定时间段内已有拼团活动 | 创建 |
| 409 | `GROUP_BUY_NOT_ACTIVE` | 拼团商品已下架 | 下单 |
| 409 | `GROUP_BUY_NOT_STARTED` | 拼团尚未开始 | 下单 |
| 409 | `GROUP_BUY_EXPIRED` | 拼团已结束 | 下单 |
| 409 | `GROUP_BUY_SOLD_OUT` | 拼团库存不足 | 下单 |
| 409 | `GROUP_BUY_LIMIT_EXCEEDED` | 每人限购 X，已购 Y | 下单 |
| 409 | `GROUP_BUY_MENU_ITEM_UNAVAILABLE` | 菜品已下架或不可售 | 下单 |

**字段映射**：

| 列表字段 | 取值 | 说明 |
|----------|------|------|
| 菜品名 | 需额外调菜品接口或前端缓存 menu_item_id → name 的映射 | 创建时前端记下菜品名 |
| 原价 | `original_price` | 只读 |
| 拼团价 | `group_price` | |
| 折扣率 | `discount_rate` | 前端显示为 `Math.round(discount_rate * 100)` + `%` |
| 库存 | `sold_count + "/" + total_quota` | 已售/总量 |
| 剩余 | `total_quota - sold_count` | 可前端算 |
| 状态标签 | 根据 `is_active` + 时间判断 | 见下方状态逻辑 |
| 分享码 | `share_code` | 可复制 |
| 时间 | `start_at` ~ `end_at` | |

**状态判断逻辑（前端）**：

```typescript
function getStatus(item): 'active' | 'expired' | 'inactive' | 'not_started' {
  if (!item.is_active) return 'inactive'
  const now = Date.now()
  if (new Date(item.start_at).getTime() > now) return 'not_started'
  if (new Date(item.end_at).getTime() < now) return 'expired'
  return 'active'
}
```

- `active` → 绿色标签「进行中」
- `not_started` → 蓝色标签「未开始」
- `expired` → 灰色标签「已过期」
- `inactive` → 红色标签「已下架」

### 7.3 新建/编辑页

**接口**：
- 创建：`POST /api/v1/group-buy/items`
- 更新：`PATCH /api/v1/group-buy/items/:id`
- 获取菜品列表：`GET /api/v1/menu/categories` + 菜品（现有接口）

**表单字段**：

| 字段 | 组件 | 说明 |
|------|------|------|
| 菜品选择 | Select/SearchSelect | 调现有菜品列表接口，仅 `is_available=true` |
| 拼团价 | InputNumber | 输入后实时校验 < 原价，显示折扣率预览 |
| 总库存 | InputNumber | > 0 |
| 每人限购 | InputNumber | >= 1 |
| 活动时间 | DatePicker.RangePicker | 结束时间 > 开始时间 |
| 排序权重 | InputNumber | 可选，默认 0 |

**原价展示**：选择菜品后，从菜品数据中读取 `price` 显示为「原价：¥97.00」（只读）。

**折扣率预览**：输入拼团价时实时计算并显示：

```
拼团价: [  59.9  ]  →  约 6.2 折（省 ¥37.10）
```

前端计算：
```typescript
const discountRate = groupPrice / originalPrice
const savedAmount = originalPrice - groupPrice
// 显示：`${(discountRate * 10).toFixed(1)} 折（省 ¥${savedAmount.toFixed(2)}）`
```

**提交逻辑**：

```typescript
// 创建
const res = await api.post('/api/v1/group-buy/items', {
    menu_item_id: selectedMenuItem.id,
    group_price: form.groupPrice,
    total_quota: form.totalQuota,
    max_per_user: form.maxPerUser,
    start_at: form.dateRange[0].toISOString(),
    end_at: form.dateRange[1].toISOString(),
    sort_order: form.sortOrder || 0,
})

// 编辑（仅传修改的字段）
const res = await api.patch(`/api/v1/group-buy/items/${id}`, {
    group_price: form.groupPrice,    // 可选

    max_per_user: form.maxPerUser,   // 可选
    is_active: form.isActive,        // 可选
    sort_order: form.sortOrder,      // 可选

```

| 库存进度 | `sold_count` / `total_quota` | 进度条：`sold_count / total_quota * 100` |
| 剩余库存 | `total_quota - sold_count` | 前端计算 |
| 限购提示 | `max_per_user` | 「每人限购 N 件」 |

**分享码/分享链接**：列表中不需要，分享功能放在详情页。

### 8.4 下单流程

**接口**：`POST /api/v1/group-buy/orders`

```typescript
// 1. 点击「立即拼团」
const res = await api.post('/api/v1/group-buy/orders', {
    group_buy_item_id: item.id,
    quantity: selectedQuantity,
})

// 2. 后端返回
// { order_id: 13693, status: "PENDING_PAYMENT", message: "created" }

// 3. 跳转支付（复用现有支付流程）
router.push(`/payment?order_id=${res.order_id}&amount=${item.group_price * selectedQuantity}`)
```

**下单后的流程与普通订单一致**：订单创建 → 调现有支付接口 → 支付回调 → 订单状态变为 PAID。

**错误处理**：

```typescript
const orderErrors: Record<string, string> = {
    'GROUP_BUY_NOT_FOUND': '拼团商品不存在',
```

建议在详情页做以下**前置校验**减少无效请求：
- `total_quota - sold_count <= 0` → 显示「已售罄」按钮置灰
- 当前时间不在 `start_at ~ end_at` 范围 → 显示倒计时或「已结束」
- `quantity` 选择器上限 = `min(max_per_user, total_quota - sold_count)`
