# 金币抵扣配置接口需求

- **需求方**：C 端 APP / H5 前端
- **日期**：2026-07-05
- **优先级**：P1
- **背景**：C 端 checkout 页面金币抵扣规则（兑换比 1:1、比例上限 10%）目前**硬编码在前端**，后端 `coin_deduction_configs` 表的配置变化时前端无法响应。

---

## 1. 当前现状

### 1.1 前端硬编码

`pages/checkout/index.vue:387-392`：

```js
maxDeductAmount() {
    return Math.floor(this.productTotal * 0.1 * 100) / 100
    //                              ^^^ 硬编码 10%
},
maxDeductCoins() {
    return Math.floor(this.maxDeductAmount)
    //                              ^^^ 隐含 1 金币 = 1 铢
},
```

### 1.2 后端配置（参考 `docs/修复文档_三语支持与金币返利配置化.md`）

```sql
SELECT * FROM coin_deduction_configs;
```

| 配置项 | 当前值 | 说明 |
|---|---|---|
| `coin_to_baht` | 1 | 1 金币 = 1 铢 |
| `max_deduct_percent` | 10 | 每单最多抵扣 10% |

总控端可以改这两项，但 C 端拿不到。

### 1.3 现有接口

`POST /api/v1/user-orders/calculate-coin-deduct` 已实现：

**请求**：
```json
{
  "order_amount": 70,
  "coins_to_use": 7
}
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "deduct_amount": 7,
    "final_amount": 63,
    "max_coins": 7,
    "order_amount": 70,
    "coin_balance": 7
  }
}
```

**问题**：响应里只有「实际抵扣金额」，**没有返回当前配置**（比例、兑换比），前端没法显示准确的「本单最多可抵 ฿X」。

---

## 2. 需求

### 2.1 接口扩展（推荐方案）

**`POST /api/v1/user-orders/calculate-coin-deduct`** 响应增加 3 个字段：

```json
{
  "code": 0,
  "data": {
    // 原有字段
    "deduct_amount": 7,
    "final_amount": 63,
    "max_coins": 7,
    "order_amount": 70,
    "coin_balance": 7,

    // 新增字段（来自 coin_deduction_configs 表）
    "max_deduct_percent": 10,        // 每单最大抵扣比例（%）
    "coin_to_baht_rate": 1,          // 金币兑换比（1 金币 = N 铢）
    "max_deduct_amount": 7.0         // 当前订单最大可抵扣金额（= order_amount × max_deduct_percent / 100）
  }
}
```

前端拿到后**直接使用**，无需硬编码：

```js
maxDeductAmount() {
    return this.coinConfig.maxDeductAmount
        || Math.floor(this.productTotal * (this.coinConfig.maxDeductPercent / 100) * 100) / 100
}
```

### 2.2 备选方案：独立配置接口

如果不想改 `calculate-coin-deduct` 响应结构，加一个独立接口：

**`GET /api/v1/user-orders/coin-deduct-config`**

返回：
```json
{
  "code": 0,
  "data": {
    "max_deduct_percent": 10,
    "coin_to_baht_rate": 1
  }
}
```

前端 checkout 页加载时调一次，缓存配置。

**前端倾向方案 2.1**——少一次请求，配置和抵扣计算结果一起返回更合理。

---

## 3. 前端配合

后端字段一返回，前端 checkout 页：

1. **data 加 `coinConfig`**：
   ```js
   coinConfig: {
       maxDeductPercent: 10,    // 默认值（接口未返回时兜底）
       coinToBahtRate: 1,
       maxDeductAmount: 0
   }
   ```

2. **`handleCoinToggle` 调接口时**保存返回的配置：
   ```js
   if (res.data.max_deduct_percent) this.coinConfig.maxDeductPercent = res.data.max_deduct_percent
   if (res.data.coin_to_baht_rate) this.coinConfig.coinToBahtRate = res.data.coin_to_baht_rate
   if (res.data.max_deduct_amount) this.coinConfig.maxDeductAmount = res.data.max_deduct_amount
   ```

3. **`maxDeductAmount` computed 改为**：
   ```js
   maxDeductAmount() {
       // 优先用后端返回的 max_deduct_amount
       if (this.coinConfig.maxDeductAmount > 0) return this.coinConfig.maxDeductAmount
       // 兜底：按 max_deduct_percent 计算
       return Math.floor(this.productTotal * (this.coinConfig.maxDeductPercent / 100) * 100) / 100
   }
   ```

4. **`maxDeductCoins` computed 改为**（按兑换比）：
   ```js
   maxDeductCoins() {
       return Math.floor(this.maxDeductAmount / this.coinConfig.coinToBahtRate)
   }
   ```

5. **UI 提示文案**「本单最多可抵 ฿X（用 N 金币）」自动跟随配置变化。

---

## 4. 验收

### 4.1 接口验收

调 `POST /api/v1/user-orders/calculate-coin-deduct`：

- ✅ 响应含 `max_deduct_percent`、`coin_to_baht_rate`、`max_deduct_amount` 三个字段
- ✅ 值与 `coin_deduction_configs` 表当前配置一致
- ✅ `max_deduct_amount` 与 `order_amount × max_deduct_percent / 100` 一致

### 4.2 配置变化验收

总控端改 `coin_deduction_configs.max_deduct_percent` 从 10 改成 20，C 端：

- 100 铢订单之前最多抵 ฿10（10 金币）
- 改后 C 端立即显示最多抵 ฿20（20 金币）

### 4.3 兑换比变化验收

`coin_to_baht` 从 1 改成 2（1 金币 = 2 铢），C 端：

- 100 铢订单（10% 上限）之前显示「用 10 金币抵 ฿10」
- 改后显示「用 5 金币抵 ฿10」（金币数 = max_deduct_amount / coin_to_baht）

---

## 5. 业务规则说明

| 配置项 | 业务含义 | 影响范围 |
|---|---|---|
| `max_deduct_percent` | 每单最多抵扣订单总额的 X% | C 端 checkout 显示 + 下单校验 |
| `coin_to_baht_rate` | 1 金币 = N 铢 | C 端金币数 ↔ 铢换算 |
| （可选）`min_order_amount` | 订单满 X 铢才能用金币 | C 端金币开关置灰判断 |

如果未来加新规则（最低订单金额、最低金币数等），建议接口一并返回。

---

## 6. 优先级

**P1** —— 不影响下单（实际抵扣金额由后端决定），但影响 UI 显示准确性。后端配置改了之后前端无法响应，可能引发用户疑问。
