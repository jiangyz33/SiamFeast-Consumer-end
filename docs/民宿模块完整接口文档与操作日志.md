### 3.3 预订管理

#### POST /hostels/bookings

创建民宿预订。

**请求体**: `HostelBookingCreate`
```json
{
  "store_id": 100,
  "room_id": 1,
  "order_source": "HOSTEL_ROOM_SERVICE",
  "extra_data": {
    "check_in_date": "2026-05-01",
    "check_out_date": "2026-05-03",
    "guest_count": 2,
    "guest_info": { "name": "张三", "phone": "0812345678" },
    "deposit_amount": 500.00
  },
  "remark": "需要安静房间",
  "coupon_id": 7,
  "cancellation_policy_id": 1,
  "special_requests": "late check-in after 22:00"
}
```

**预订流程**:
1. 验证房间存在且属于该门店
2. P2: 连住限制校验 (min_stay/max_stay)
3. 检查日期范围内房间可用
4. 计算每日房价总价（调用动态定价引擎）
5. P0: 优惠券校验与折扣计算
6. 创建 Order + HostelBooking
7. P0: 库存锁定 (行级锁 `SELECT ... FOR UPDATE`)

**权限**: CurrentUser（登录用户）

#### GET /hostels/bookings/{order_id}

获取预订详情。

#### POST /hostels/bookings/{booking_id}/confirm

确认预订。**权限**: CurrentStaff

#### POST /hostels/bookings/{booking_id}/cancel

取消预订（P0 增强）。

**流程**: 取消政策匹配 → 退款计算 → 创建退款记录 → 释放库存 → 退券恢复

**权限**: CurrentUser 或 CurrentStaff

### 3.10 P2: 续住

#### POST /hostels/bookings/{booking_id}/extend

续住（延后退房日期）。

**请求体**: `ExtendStayRequest`
```json
{ "new_check_out_date": "2026-05-05" }
```

**逻辑**:
1. 校验预订状态必须为 CHECKED_IN
2. 校验新日期 > 原退房日期
3. 校验新增日期范围房间可订
4. 计算续住差价
5. P2: 校验连住限制（总天数不超过 max_stay）
6. 锁定新增日期库存
7. 更新预订的 check_out_date / nights / room_price_total

## 四、动态定价端点（/api/v1/pricing）

### 4.1 房型 CRUD

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /room-types | 房型列表（含动态定价规则配置） |
| POST | /room-types | 创建房型 |
| GET | /room-types/{id} | 房型详情 |
| PUT | /room-types/{id} | 更新房型 |

房型创建/更新时支持传入 `season_rules`, `demand_pricing_config`, `long_stay_discounts`, `early_bird_discounts` 字段。

### 4.2 日历定价 CRUD

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /calendar | 获取日期区间价格（含动态定价计算结果） |
| POST | /calendar/{room_type_id} | 设置单日价格（日历覆盖，最高优先级） |
| POST | /calendar/{room_type_id}/batch | 批量设置区间价格 |
| GET | /calendar/{room_type_id}/{date} | 获取单日价格详情 |

**source 字段说明**:

| source 值 | 含义 |
|-----------|------|
| BASE_PRICE | 基础价格 |
| WEEKEND_PRICE | 周末价格 |
| HOLIDAY_PRICE | 节假日固定价 |
| HOLIDAY_MODIFIER | 节假日系数价 |
| CALENDAR_OVERRIDE | 日历覆盖（最高优先级） |
| +SEASON | 叠加了季节系数 |
| +DEMAND | 叠加了需求系数 |

### 4.3 节假日规则

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /holidays | 节假日规则列表 |
| POST | /holidays | 创建节假日规则 |
| PUT | /holidays/{id} | 更新节假日规则 |
| POST | /holidays/{store_id}/sync | **同步泰国假期**（Nager.Date API） |

**同步规则**:
- 已存在的假期不覆盖（保留管理员调整的 modifier）
- 重大假期（宋干节/跨年）默认 modifier=3.0
- 普通假期默认 modifier=1.3

### 4.4 新增管理端点

| 方法 | 路径 | 说明 |

## 五、定价计算引擎

### 5.1 优先级链

```
┌─────────────────────────────────────────────────────────────┐
│               第一层：每日单价（优先级链）                       │
│                                                             │
│  ① 日历覆盖 (CALENDAR_OVERRIDE)  ← 管理员手动设价            │
│  ② 节假日固定价 (HOLIDAY_PRICE)   ←房型 holiday_price        │
│  ③ 节假日系数 (HOLIDAY_MODIFIER)  ← base × holiday.modifier  │
│  ④ 周末价格 (WEEKEND_PRICE)       ← 房型 weekend_price       │
│  ⑤ 基础价格 (BASE_PRICE)          ← 房型 base_price          │
│                                                             │
│  在 ②~⑤ 基础上依次叠加:                                      │
│    × 季节系数 (season_rules)                                  │
│    × 需求系数 (demand_pricing_config)                         │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│               第二层：预订折扣（叠加在总价上）                   │
│                                                             │
│  × (1 - 长住折扣%)    ← 连住 N 晚                            │
│  × (1 - 早鸟折扣%)    ← 提前 N 天预订                        │
│  - 优惠券抵扣         ← 已有优惠券系统                        │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  最终总价 = Σ(每日单价) × 长住折扣 × 早鸟折扣 - 优惠券         │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 JSONB 数据格式

**season_rules**: `[{"name":"旺季","start_month":11,"end_month":2,"modifier":1.3,"enabled":true}]`

**demand_pricing_config**: `{"enabled":true,"lookahead_days":14,"tiers":[{"occupancy_max":30,"modifier":0.85,"label":"极低需求"},...]}`

**long_stay_discounts**: `[{"min_nights":7,"discount_pct":10,"label":"连住7晚9折","enabled":true}]`

**early_bird_discounts**: `[{"advance_days":30,"discount_pct":10,"label":"提前30天9折","enabled":true}]`

### 5.3 季节系数匹配

支持跨年月份范围（如 11月~2月 → start=11, end=2），`enabled=false` 的规则跳过。

### 5.4 需求系数匹配

1. 读取 room_type.demand_pricing_config
2. 如果 enabled=false → 返回 1.0
3. 计算门店未来 N 天平均入住率: `BLOCKED记录数 / (活跃房间数 × lookahead_days) × 100`
4. 按 occupancy_max 升序匹配第一个 >= 当前入住率的档位

### 5.5 折扣匹配

- **长住**: 遍历 long_stay_discounts，取 enabled=true 且 min_nights <= 实际天数中 discount_pct 最大的
- **早鸟**: 遍历 early_bird_discounts，取 enabled=true 且 advance_days <= 实际提前天数中 discount_pct 最大的
