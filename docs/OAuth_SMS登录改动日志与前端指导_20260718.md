## 第一部分：改动日志（工程视角）

### 1.1 改动背景

前端方案变更：弃用 Firebase UTS 付费插件（¥118 + 踩坑多），改用 HBuilderX 内置 OAuth 模块（免费）+ 后端自建 SMS。需要后端新增 4 个接口，并把数据库字段从 "Firebase 单一方案" 重命名为 "通用 OAuth 方案"。

### 1.2 数据库改动

**Migration**：`migrations/000058_oauth_rename_provider_fields.up.sql`

| 操作 | 详情 |
|---|---|
| 字段重命名 | `users.firebase_uid → users.provider_uid` |
| 字段重命名 | `users.auth_provider → users.provider` |
| 索引重建 | `idx_users_firebase_uid → idx_users_provider_uid` |
| 新增索引 | `idx_users_phone`（短信登录按 phone 查） |

**字段值约定**（`provider` 列）：

| provider 值 | provider_uid 值 | 含义 |
|---|---|---|
| `password` | NULL | 邮箱密码注册的本地用户 |
| `phone` | 手机号本身（如 `+66812345678`） | 短信验证码登录用户 |
| `google` | Google `sub`（如 `115682347890123456789`） | Google OAuth 用户 |
| `facebook` | Facebook `id`（如 `10234657890123456`） | Facebook OAuth 用户 |
| `firebase` | Firebase UID（历史数据） | 老 Firebase 用户（向后兼容） |

### 2.2 接口定义（4 个新接口）

#### 2.2.1 POST `/api/v1/auth/google-login`

**请求**：
```json
{
  "id_token": "eyJhbGciOiJSUzI1NiIs...",      // 必填，uni.login 拿到
  "access_token": "ya29.a0ARrdaM..."           // 选填，备用
}
```

**响应**：
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 259200,
  "role": "consumer",
  "user_id": 123,
  "is_new_user": true,
  "user": {
    "id": 123,
    "nickname": "John Doe",
    "phone": null,
    "avatar_url": "https://lh3.googleusercontent.com/..."
  },
  "email": "john@gmail.com",
  "google_access_token": "ya29..."
}
```

**错误码**：
| HTTP | code | 处理建议 |
|---|---|---|
| 503 | `GOOGLE_NOT_CONFIGURED` | 后端未配置，联系后端 |
| 401 | `GOOGLE_TOKEN_INVALID` | token 过期，重新调 `uni.login` |
| 401 | `GOOGLE_AUDIENCE_MISMATCH` | Client ID 不匹配，检查 Google Cloud 配置 |
| 403 | `ACCOUNT_DISABLED` | 账号被禁用 |

#### 2.2.3 POST `/api/v1/auth/sms/send`

**请求**：
```json
{
  "phone_number": "+66812345678",   // 必填，E.164 格式（+国家码+号码）
  "scene": "login"                  // 必填：login / register / reset_password / change_phone
```

**响应**：
```json
{
```

|---|---|---|
| 400 | `INVALID_PHONE` | 号码格式错（必须 `+` 开头 E.164） |
| 429 | `RATE_LIMITED` | 触发频控，提示用户等待 |
| 503 | `SMS_NOT_CONFIGURED` | 后端未配置短信服务 |
| 500 | `SMS_SEND_FAILED` | 短信服务商调用失败 |

**请求**：
```json
{
  "phone_number": "+66812345678",   // 必填

  "scene": "login"                  // 选填，默认 login
```

**响应**：
```json
{
  "access_token": "...",

  "expires_in": 259200,
  "role": "consumer",
  "user_id": 123,
```

### 2.3 核心设计理念：「验证码即注册」

后端采用**业界主流的"登录即注册"模式**（参考微信 / GitHub / 抖音）：

```
验证码验证通过
       ↓
查找用户
   ├─ 找到 → 登录成功 (is_new_user=false)
   └─ 没找到 → 自动创建账号 (is_new_user=true)
```

**前端只需根据 `is_new_user` 字段决定跳转**：
- `true` → 跳"完善信息页"（设昵称/密码/邀请码）
- `false` → 直接进首页

**优点**：用户少填一次表单（手机号已验证 = 信任），提升转化率。

#### TypeScript 完整示例

```typescript
// api/auth.ts
const API_BASE = import.meta.env.VITE_API_BASE || ''

export async function sendSMSCode(phoneNumber: string, scene: 'login' | 'register' | 'reset_password' = 'login') {
  const res = await fetch(`${API_BASE}/api/v1/auth/sms/send`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ phone_number: phoneNumber, scene }),
  })
  return res.json()
}

export async function smsLogin(phoneNumber: string, code: string, scene: string = 'login') {
  const res = await fetch(`${API_BASE}/api/v1/auth/sms/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ phone_number: phoneNumber, code, scene }),
  })
  if (!res.ok) throw await res.json()
  return res.json()
}

// 需要带 token 的接口
async function authFetch(token: string, url: string, body: any, method = 'POST') {
  return fetch(`${API_BASE}${url}`, {
    method,
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`,
    },
    body: JSON.stringify(body),
  })
}

// 注册主流程
export async function registerWithSMS(params: {
  phoneNumber: string
  code: string
  password: string
  nickname: string
  inviteCode?: string  // 选填
}) {
  // 1. 验证码登录（自动注册）
  const loginResult = await smsLogin(params.phoneNumber, params.code, 'register')
  const { access_token, is_new_user } = loginResult

  if (!is_new_user) {
    // 老用户（已注册过），直接登录
    return { ...loginResult, isExistingUser: true }
  }

  // 2. 新用户，补全信息（3 个接口并行）
  const tasks: Promise<Response>[] = [
    authFetch(access_token, '/api/v1/users/me', { nickname: params.nickname }, 'PATCH'),
    authFetch(access_token, '/api/v1/password/change', {
      old_password: '',  // 新用户空
      new_password: params.password,
    }),
  ]

  if (params.inviteCode) {
    tasks.push(authFetch(access_token, '/api/v1/referrals/bind', { invite_code: params.inviteCode }))
  }

  const results = await Promise.allSettled(tasks)

  // 检查补全结果（部分失败不阻断登录）
  const failed = results.filter(r => r.status === 'rejected')
  if (failed.length > 0) {
    console.warn('[register] 部分信息补全失败', failed)
    // 不 throw，让用户进首页，事后引导去设置页修复
  }

  return { ...loginResult, isExistingUser: false }
}
```

#### Vue 3 组件示例

```vue
<template>
  <div class="register-page">
    <input v-model="form.phoneNumber" placeholder="+66..." />
    <input v-model="form.password" type="password" placeholder="密码（≥6位）" />
    <input v-model="form.nickname" placeholder="用户名" />
    <input v-model="form.inviteCode" placeholder="邀请码（选填）" />

    <div class="code-row">
      <input v-model="form.code" placeholder="6 位验证码" maxlength="6" />
      <button @click="handleSendCode" :disabled="cooldown > 0">
        {{ cooldown > 0 ? `${cooldown}s` : '获取验证码' }}
      </button>
    </div>

    <button @click="handleRegister" :disabled="loading">注册</button>
  </div>

<script setup lang="ts">
import { ref, reactive } from 'vue'
import { useRouter } from 'vue-router'
import { sendSMSCode, registerWithSMS } from '@/api/auth'
import { useUserStore } from '@/stores/user'

const router = useRouter()
const userStore = useUserStore()

const form = reactive({
  phoneNumber: '',
  password: '',
  nickname: '',
  inviteCode: '',
  code: '',
})

const cooldown = ref(0)
const loading = ref(false)

// 校验
function validate(): string | null {
  if (!form.phoneNumber.match(/^\+\d{7,15}$/)) return '手机号格式不正确'
  if (form.password.length < 6) return '密码至少 6 位'
  if (!form.nickname.trim()) return '请填写用户名'
  if (!form.code.match(/^\d{6}$/)) return '请填写 6 位验证码'
  return null
}

async function handleSendCode() {
  if (!form.phoneNumber.match(/^\+\d{7,15}$/)) {
    alert('手机号格式不正确')
    return
  }
  try {
    await sendSMSCode(form.phoneNumber, 'register')
    cooldown.value = 60
    const timer = setInterval(() => {
      cooldown.value--
      if (cooldown.value === 0) clearInterval(timer)
    }, 1000)
  } catch (e: any) {
    if (e.code === 'RATE_LIMITED') {
      alert('操作太频繁，请稍后重试')
    } else {
      alert(e.message || '发送失败')
    }
  }
}

async function handleRegister() {
  const err = validate()
  if (err) {
    alert(err)
    return
  }

  loading.value = true
  try {
    const result = await registerWithSMS({
      phoneNumber: form.phoneNumber,
      code: form.code,
      password: form.password,
      nickname: form.nickname,
      inviteCode: form.inviteCode || undefined,
    })

    userStore.setToken(result.access_token, result.refresh_token)
    userStore.setUser(result.user)

    if (result.isExistingUser) {
      alert('该手机号已注册，已为您直接登录')
    }
    router.push('/home')
  } catch (e: any) {
    const msgMap: Record<string, string> = {
      CODE_INVALID: '验证码错误',
      CODE_EXPIRED: '验证码已过期，请重新发送',
      CODE_TOO_MANY_ATTEMPTS: '尝试次数过多，请重新发送',
      RATE_LIMITED: '操作太频繁',
      PHONE_FORMAT_INVALID: '手机号格式不正确',
    }
    alert(msgMap[e.code] || e.message || '注册失败')
  } finally {
    loading.value = false
  }
}
</script>
```

```typescript
export async function loginWithGoogle() {
  // 1. 调 uni.login 拿 Google id_token
  const [, authResult] = await uni.login({ provider: 'google' }) as any

  return res.json()
}
```

### 2.6 关键约束（前端必看）

#### ⚠️ 1. 手机号必须是 E.164 格式

```
✅ 正确：+66812345678（泰国）
✅ 正确：+8613800138000（中国）
❌ 错误：0812345678（缺国家码）
❌ 错误：66812345678（缺 +）
❌ 错误：+66 812 345 678（有空格）
```

**前端必须做客户端校验**（正则 `^\+\d{7,15}$`），避免无效请求打到后端。

#### ⚠️ 2. `is_new_user` 字段决定跳转逻辑

```typescript
const result = await smsLogin(phone, code)
if (result.is_new_user) {
  router.push('/profile/setup')  // 新用户 → 完善信息
} else {
  router.push('/home')           // 老用户 → 直接进
}
```

#### ⚠️ 3. 验证码 60 秒频控

前端按钮做 60 秒倒计时，避免用户狂点触发 `RATE_LIMITED`。

#### ⚠️ 4. 验证码 5 分钟有效

`/auth/sms/send` 返回 `expires_in: 300`。前端可以做倒计时提示（"验证码 5 分钟内有效"）。

#### ⚠️ 5. 不存在"独立的注册接口"

后端采用「验证码即注册」模式，**没有单独的 `/auth/register` 接口**。注册流程 = SMS 登录 + 后续补全（3 个接口）。这是系统设计，**不要问后端要"注册接口"**。

#### ⚠️ 6. access_token 过期处理

```typescript
// axios 拦截器
if (err.response?.status === 401 && err.response.data?.code === 'TOKEN_INVALID') {
  // access_token 过期，用 refresh_token 换新的
  const refreshRes = await fetch('/api/v1/auth/refresh', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ refresh_token: localStorage.getItem('refresh_token') }),
  })
  if (refreshRes.ok) {
    const newToken = (await refreshRes.json()).access_token
    localStorage.setItem('access_token', newToken)
    return retryOriginalRequest()
  } else {
    // refresh 也失败，跳登录页
    router.push('/login')
  }
}

// 单会话踢人
if (err.response?.data?.code === 'TOKEN_KICKED') {
  alert('账号已在其他设备登录')
  router.push('/login')
}
```

## 附录：常见问题 FAQ

### Q1：为什么没有"独立注册接口"？

A：系统采用「验证码即注册」模式（业界主流，参考微信 / GitHub / 抖音）。验证码验证 = 创建账号，比传统"先填表→提交→等审核"流程转化率高得多。注册时填的密码/用户名/邀请码通过独立接口补全，每个接口职责单一，便于维护。

### Q2：用户注册时邀请码填错了怎么办？

A：邀请码绑定失败不阻断注册。用户登录后在"账号设置"页可以再绑（`POST /referrals/bind`）。

### Q3：能用短信验证码做"改密码"吗？

A：可以。`/auth/sms/send` 接收 `scene` 参数（`reset_password` / `change_phone`），用对应 scene 发码。前端在改密码页用 `scene=reset_password` 调发码接口，验证码通过后调 `/password/reset`。

### Q4：Google 登录拿到的 `id_token` 直接用，不行吗？为什么要换自家 JWT？

A：Firebase/Google id_token 1 小时就过期，用户每次操作都要重新授权，体验差。自家 JWT 默认 72 小时，配合 refresh_token（30 天）能实现"一次登录长期使用"。

### Q5：短信发到泰国号码收不到？

A：检查 3 件事：
1. 号码必须是 E.164 格式（`+66812345678` 不是 `0812345678`）
2. Twilio 账号是否是 Trial（Trial 只能发到已验证号码）
3. Twilio 是否开通了国际短信（特别是泰国）

### Q6：单会话踢人是什么？

A：同一账号在 A 设备登录后，又在 B 设备登录 → A 设备自动下线（返回 `TOKEN_KICKED`）。前端识别这个错误码后清 token + 跳登录页。

### Q7：access_token 和 refresh_token 的区别？

| token | 作用 | 有效期 | 存哪 |
|---|---|---|---|
| `access_token` | 调所有业务接口 | 72 小时 | localStorage |
| `refresh_token` | access_token 过期后换新的 | 30 天 | localStorage（更安全：HttpOnly Cookie） |
