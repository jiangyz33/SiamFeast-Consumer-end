# `/campaigns` 活动接口补充「适用范围」字段 — 后端工单

> 日期：2026-08-02
> 发件人：前端 jiangyz33
> 收件人：后端
> 优先级：P2（提升活动信息透明度，避免用户进店后才发现不适用）
> 关联接口：
> - `GET /api/v1/campaigns`（活动列表）
> - `GET /api/v1/campaigns/:id`（活动详情）

---

## 1. 背景

活动详情弹窗（`components/campaign-detail-modal.vue`）当前能展示的字段：名称、类型、时间窗口、规则描述、折扣/积分/金币、日期模式、券列表。

但**用户看不到"这个活动在哪些门店、哪些商品、多少金额门槛下能享受"**，导致：

- 用户看到"全场 8 折"活动 → 进店后被收银员告知"这家店不参与"
- 用户买完发现只有"饮品"分类参与活动，但用户买的是"生鲜"
- FULL_REDUCTION 类活动（满 200 减 30），用户不知道门槛，凑单后才发现达不到

后端当前 `/campaigns` 响应**未包含**以下字段（已查所有现有回执文档无相关定义）。

## 2. 需求

### 2.1 新增字段清单

`GET /campaigns` 和 `GET /campaigns/:id` 响应的每个 campaign 对象上新增以下字段：

```jsonc
{
  // ... 原字段（id / type / name / name_en / name_th / description / image_url / start_date / end_date / rules）
  "applies_to_all_stores": true,
  "store_ids": [55, 60, 88],          // applies_to_all_stores=false 时才有意义
  "store_count": 3,                     // 便捷字段：适用门店数量（前端不必数 store_ids 长度）
  "applicable_categories": [12, 18],    // 适用分类 id 列表
  "applicable_category_names": {        // 便捷字段：分类名（避免前端再查分类接口）
    "zh": ["饮品", "主食"],
    "en": ["Drinks", "Main dishes"],
    "th": ["เครื่องดื่ม", "อาหารหลัก"]
  },
  "applicable_to_all_categories": true, // true=全部分类适用，false=仅 applicable_categories 列出
  "applicable_menu_items": [256, 257],  // 适用商品 id 列表（可选，如果活动是按单品粒度配置）
  "min_order_amount": 200               // 活动门槛（满 X 才能享受），0 或 null = 无门槛
}
```

### 2.2 字段语义

| 字段 | 类型 | 取值规则 |
|---|---|---|
| `applies_to_all_stores` | bool | `true` = 全部门店；`false` = 仅 `store_ids` 列出 |
| `store_ids` | number[] | 适用门店 id 列表（`applies_to_all_stores=true` 时可返回空数组或省略）|
| `store_count` | number | 便捷字段：适用门店数。`applies_to_all_stores=true` 时返回总门店数 |
| `applicable_to_all_categories` | bool | `true` = 全部分类；`false` = 仅 `applicable_categories` 列出 |
| `applicable_categories` | number[] | 适用分类 id（`applicable_to_all_categories=true` 时可省略）|
| `applicable_category_names` | object | 多语言分类名 `{zh, en, th}`，每个值是字符串数组 |
| `applicable_menu_items` | number[] \| null | 仅按单品粒度配置的活动返回；按分类时返回 null |
| `min_order_amount` | number | 活动门槛（铢）。0 或 null = 无门槛 |

### 2.3 不同活动类型的字段填充建议

| 活动类型 | 适用门店 | 适用分类 | 适用商品 | 门槛 |
|---|---|---|---|---|
| DISCOUNT（全场 X 折）| ✅ 必填 | ✅ 必填 | 通常不需要 | 0 或必填 |
| FULL_REDUCTION（满减）| ✅ 必填 | ✅ 必填 | 通常不需要 | ✅ 必填 |
| COUPON_GRANT（赠券）| ✅ 必填 | 可选（赠券本身有 min_spend）| 可选 | 跟随券 |
| SPECIAL_DATE（双号日 / 节日）| ✅ 必填 | 可选 | 可选 | 跟随券或活动 |

## 3. 前端落点（字段一上线即启用）

### 3.1 活动详情弹窗（`components/campaign-detail-modal.vue`）

在规则区（`rules-section`）追加展示行：

```vue
<!-- 适用门店 -->
<view v-if="campaign.applies_to_all_stores === false && campaign.store_count" class="rules-hint">
  <text class="rules-hint-text">📍 {{ t('campaign.applicableStores', { n: campaign.store_count }) }}</text>
</view>
<view v-else class="rules-hint">
  <text class="rules-hint-text">📍 {{ t('campaign.allStores') }}</text>
</view>

<!-- 适用分类 -->
<view v-if="campaign.applicable_to_all_categories === false && applicableCategoryText" class="rules-hint">
  <text class="rules-hint-text">🍽️ {{ t('campaign.applicableCategories') }}：{{ applicableCategoryText }}</text>
</view>

<!-- 活动门槛 -->
<view v-if="campaign.min_order_amount > 0" class="rules-hint">
  <text class="rules-hint-text">💰 {{ t('campaign.minSpend', { amount: campaign.min_order_amount }) }}</text>
</view>
```

新增 i18n 文案（三语）：
| key | zh | en | th |
|---|---|---|---|
| `campaign.applicableStores` | 适用 {n} 家门店 | {n} stores | ใช้ได้ {n} สาขา |
| `campaign.allStores` | 全部门店适用 | All stores | ทุกสาขา |
| `campaign.applicableCategories` | 适用分类 | Categories | หมวดหมู่ |
| `campaign.minSpend` | 满 ฿{amount} 可用 | Min. spend ฿{amount} | ขั้นต่ำ ฿{amount} |

### 3.2 结算页凑单提示（`pages/checkout/index.vue`，可选第二期）

如果 `campaign.min_order_amount > productTotal`，在结算页提示"再加 ฿X 即可享受 {活动名}"，引导凑单。

## 4. 兼容性

- 字段未返回时（老后端）：前端按"无信息"处理，规则区不展示这几行，不报错。
- 部分活动返回部分字段：前端按字段存在性逐项展示。
- 多语言分类名缺失：前端用分类 id 兜底（如有）或省略该行。

## 5. 验证用例

### 5.1 全门店 + 全分类活动

```jsonc
{
  "type": "DISCOUNT",
  "applies_to_all_stores": true,
  "store_count": 18,
  "applicable_to_all_categories": true,
  "min_order_amount": 0
}
```

前端展示：
```
📍 全部门店适用
• 自动应用
```

### 5.2 部分门店 + 部分分类活动

```jsonc

  "applies_to_all_stores": false,
  "store_count": 3,
  "applicable_to_all_categories": false,
  "applicable_category_names": {
    "zh": ["饮品", "甜品"],
    "en": ["Drinks", "Desserts"],
    "th": ["เครื่องดื่ม", "ของหวาน"]
```

```
📍 适用 3 家门店
🍽️ 适用分类：饮品、甜品
💰 满 ฿200 可用
• 自动应用
```

## 6. 性能 / 实现建议

- `store_count` / `applicable_category_names` 是便捷字段，后端在序列化时一次性 join 好返回，避免前端再发 N 次请求查门店/分类详情。
- 分类名三语直接从 `menu_categories` 表的 `name` / `name_en` / `name_th` 取。
- 门店计数可直接 `count(store_ids)` 或 join 总店数（`applies_to_all_stores=true` 时）。
- 如果当前数据模型中活动没有"适用分类"概念（即所有活动都默认全分类），可先返回 `applicable_to_all_categories: true` 占位，后续按产品需求再细化。

## 7. 优先级建议

| 字段 | 优先级 | 原因 |
|---|---|---|
| `applies_to_all_stores` + `store_count` | **P1** | 直接影响用户进店预期，避免到店被拒 |
| `min_order_amount` | **P1** | 影响下单决策，结算页凑单提示强依赖 |
| `applicable_to_all_categories` + `applicable_category_names` | **P2** | 提升透明度但非阻塞 |
| `applicable_menu_items` | **P3** | 仅特殊单品活动才需要，可延后 |

---

## 联调要点

- 字段缺失时前端按现状展示（不报错、不阻塞）
- 字段类型：`store_ids` / `applicable_categories` 必须是 number[]，不要返回逗号分隔字符串
- `applies_to_all_stores=false` 但 `store_ids` 为空数组 → 前端按"无适用门店"处理（隐藏活动或不展示）
- 多语言字段缺失某一种语言时，前端按 `zh → en → th` 顺序兜底
