## 三、改动 1:更改绑定手机号

### 3.1 接口契约

#### 接口 1.1 发送换绑验证码

```
POST /api/v1/change-phone/send-sms
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求体**:
```json
{
  "type": "old",
  "phone_number": "+66812345678"
}
```

| 字段 | 类型 | 必填 | 取值 |
|---|---|---|---|
| `type` | string | ✅ | `"old"` / `"new"` |
| `phone_number` | string | ✅ | E.164 格式(`+` 开头)|

**响应**(200):
```json
{
  "expires_in": 300,
  "is_test": false,
  "mode": "sms"
}
```

#### 接口 1.2 提交换绑

```
POST /api/v1/change-phone
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求体**:
```json
{
  "old_phone": "+66812345678",
  "old_code": "123456",
  "new_phone": "+66899999999",
  "new_code": "654321"
}
```

**响应**(200):
```json
{
  "code": 0,
  "message": "手机号更改成功",
  "data": {
    "new_phone": "+66899999999"
  }
}
```

### 3.2 错误码核查

| HTTP | code | C 端文案 | 后端确认 |
|---|---|---|---|
| 400 | `INVALID_TYPE` | 参数错误 | ⬜ |
| 400 | `NEW_PHONE_SAME_AS_OLD` | 新手机号不能与旧手机号相同 | ⬜ |
| 403 | `NO_PHONE_BOUND` | 当前账号未绑定手机号 | ⬜ |
| 400 | `OLD_PHONE_MISMATCH` | 旧手机号与当前账号绑定不符 | ⬜ |
| 409 | `PHONE_ALREADY_BOUND` | 该手机号已被其他账号使用 | ⬜ |
| 429 | `RATE_LIMITED` | 请求过于频繁,请稍后再试 | ⬜ |
| 400 | `OLD_CODE_INVALID` | 旧手机号验证码错误或已失效 | ⬜ |
| 400 | `NEW_CODE_INVALID` | 新手机号验证码错误或已失效 | ⬜ |
| 429 | `PHONE_CHANGE_LIMIT` | 本月已更改过手机号,每月只能更改一次 | ⬜ |
| 400 | `CODE_TOO_MANY_ATTEMPTS` | 验证码尝试次数过多,请重新发送 | ⬜ |

### 3.3 C 端要确认的疑问

1. ⬠ `GET /api/v1/users/me` 返回的 `phone` 字段是否完整手机号?还是脱敏(`+66812****78`)?
2. ⬠ 换绑成功后,**前端是否需要主动跳转登录页**?(文档说后端不自动清 session)

## 四、改动 2:积分商城兑换选门店

### 4.1 接口契约(扩展)

```
POST /api/v1/mall/products/:id/redeem
Authorization: Bearer <access_token>
Content-Type: application/json
```

**请求体**:
```json
{
  "product_id": 1,
  "store_id": 55,
  "pickup_time": "2026-07-27T10:00:00+07:00"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `product_id` | int | ✅ | 兑换的商品 ID |
| `store_id` | int | ✅(新增) | 提货门店 ID |
| `pickup_time` | string | ✅(新增) | ISO 8601 + 时区,必须 > now + 24h |

**响应**(201):
```json
{
  "order_id": 123,
  "unique_code": "abc-def-123"
}
```

### 4.2 错误码核查

| HTTP | code | C 端文案 | 后端确认 |
|---|---|---|---|
| 400 | `PICKUP_TIME_TOO_SOON` | 预约时间必须至少提前 24 小时 | ⬜ |
| 400 | `STOCK_SOLD_OUT` | 已兑完 | ⬜ |
| 400 | `INVALID_STORE` | 门店不存在或未启用 | ⬜ |
| 400 | `INVALID_PRODUCT` | 商品不存在 | ⬜ |

### 4.3 C 端要确认的疑问

1. ⬠ `recipient_name` 和 `recipient_phone` 字段是否还需要?(对接文档没提)
2. ⬠ `store_id` 从哪个接口拿门店列表?`GET /stores`?
3. ⬠ 兑换记录接口 `GET /mall/orders` 是否返回 `store_id` 和 `pickup_time`?

## 五、改动 3:任务系统

### 5.1 接口契约

#### 接口 3.1 任务列表

```
GET /api/v1/tasks
Authorization: Bearer <access_token>
```

**响应**:
```json
{
  "items": [
    {
      "id": 1,
      "user_id": 105,
      "task_id": 1,
      "progress": 2,
      "status": "IN_PROGRESS",
      "task": {
        "id": 1,
        "name": "邀请好友",
        "name_en": "Invite Friends",
        "name_th": "เชิญเพื่อน",
        "task_type": "INVITE",
        "target_count": 3,
        "reward_type": "POINT",
        "reward_amount": 50,
        "description": "邀请 3 位好友注册,得 50 积分"
      }
    }
  ]
}
```

**字段说明**:
| 字段 | 取值 |
|---|---|
| `status` | `IN_PROGRESS` / `COMPLETED` / `CLAIMED` |
| `task_type` | `INVITE` / `PURCHASE` / `SIGN_IN` / `CUSTOM` |
| `reward_type` | `POINT` / `COIN` / `COUPON` |

#### 接口 3.2 领取任务奖励

```
POST /api/v1/tasks/:id/claim
Authorization: Bearer <access_token>
```

**响应**(200):
```json
{
  "reward_type": "POINT",
  "reward_amount": 50,
  "task_id": 1
}
```

### 5.2 错误码核查

| HTTP | code | C 端文案 | 后端确认 |
|---|---|---|---|
| 400 | `TASK_NOT_CLAIMABLE` | 任务未完成或已领取 | ⬜ |
| 404 | `TASK_NOT_FOUND` | 任务不存在 | ⬜ |

### 5.3 C 端要确认的疑问

1. ⬠ `GET /tasks` 返回的 `id` 字段是 user_task.id 还是 task.id?(影响 claim 接口传哪个)

3. ⬠ `reward_type=COUPON` 时,`reward_amount` 是 coupon_id 还是数量?
4. ⬠ 任务有 `start_time / end_time` 字段返回吗?(判断任务有效期)

## 七、改动 5:生日弹窗 + 领取

### 7.1 接口契约

#### 接口 5.1 查生日状态

```
GET /api/v1/birthday-status
Authorization: Bearer <access_token>
```

**响应**:
```json
{
  "is_birthday_today": true,
  "birthday": "1990-07-24",
  "claimable": true,
  "reward_type": "COIN",
  "reward_amount": 100,
  "already_claimed": false,
  "reason": ""
}
```

**字段说明**:
| 字段 | 取值 |
|---|---|
| `reward_type` | `COIN` / `POINT` / `COUPON` |
| `reason`(claimable=false 时) | `disabled` / `not_birthday_today` / `claimed` / `no_birthday` |

#### 接口 5.2 领取生日奖励

```
POST /api/v1/birthday/claim
Authorization: Bearer <access_token>
```

**响应**(200):
```json
{
  "reward_type": "COIN",
  "reward_amount": 100,
  "grant_id": 12345,
  "coin_balance_after": 250
}
```

### 7.2 错误码核查

| HTTP | code | C 端文案 | 后端确认 |
|---|---|---|---|
| 400 | `not_birthday_today` | 今天不是您的生日 | ⬜ |
| 400 | `already_claimed` | 已领取过今年的生日奖励 | ⬜ |
| 400 | `disabled` | 生日奖励暂未开启 | ⬜ |
| 400 | `no_birthday` | 请先设置生日 | ⬜ |
| 400 | `BIRTHDAY_COUPON_UNAVAILABLE` | 生日券暂不可用 | ⬜ |

### 7.3 C 端要确认的疑问

1. ⬠ `birthday-status` 返回的 `birthday` 是完整日期(`1990-07-24`)还是只 MM-DD?
2. ⬠ `claim` 成功响应里,如果是 `POINT` 类型,字段名是 `point_balance_after`?还是统一不返回?
3. ⬠ 如果是 `COUPON` 类型,`reward_amount` 是 1(张数)还是 coupon_id?
4. ⬠ **App 启动时频繁调 `/birthday-status`** 是否会触发限流?建议前端多久调一次?

## 十二、风险与备选

### 12.1 接口字段不一致风险

如果后端字段和文档不一致,**C 端要返工**。建议**核查清楚再开工**。

### 12.2 总店端未对接的影响

如果 admin 接口没对接:
- ❌ C 端金币换积分 — 没有比例配置,默认 10:1 可用
- ❌ C 端生日弹窗 — 没有奖励类型配置,claim 会失败
- ❌ C 端任务系统 — 没有任务数据,列表是空的

**建议**:总店端**必须先对接 admin 接口**,再让 C 端联调。

### 12.3 工时风险

C 端总工时 14-19h,**1 人 2 天可完成**。如果接口核查发现重大差异,**多加 1 天**。
