## 1. 问题

门店开业活动（`store_opening_configs`）含三类权益，但 `GET /stores/:store_id/opening-info` 接口**只暴露了"开业赠券"的次数限制**，未暴露"开业折扣"和"额外积分/金币"的次数限制。

前端 `pages/dinein/index.vue` 当前消费的字段：

```jsonc
{
  "is_opening_active": true,
  "days_left": 5,
  "extra_points": 50,
  "extra_coins": 10,
  "discount_percent": 9,
  "coupon_ids": [22],
  "user_claimed": false,        // ← 仅"开业赠券"是否已领取（每人限领 1 次）
  "has_claimed": false
}
```

| 权益类型 | 是否暴露"次数限制"字段 | 前端可判断 |
|---|---|---|
| 开业赠券（`coupon_ids`）| ✅ `user_claimed` / `has_claimed` | 是 |
| **开业折扣**（`discount_percent`）| ❌ **无任何字段** | **否** |
| **额外积分/金币**（`extra_points` / `extra_coins`）| ❌ **无任何字段** | **否** |

## 2. 影响

### 2.1 用户感知问题

前端开业横幅（`pages/dinein/index.vue:49-75`）当前展示：

```
🎉 新店开业  剩余 5 天
   ⭐ +50 积分
   💰 +10 金币
   🏷️ 9% off
   [领取开业券]
```

用户**不知道这些权益是"开业期内每单都享"还是"仅首单享"**。

### 2.2 PERCENT 券被错误清零（连锁问题）

后端 `order/service.go:564-567` 的"防折上折"规则：

```go
if campaignDiscountRaw > 0 && (couponType == "PERCENT" || couponType == "PERCENTAGE") {
    couponDiscountRaw = 0
}
```

如果开业折扣实际是 **FIRST_ORDER_ONLY**（首单享）：
- 用户第二单以后，**已不享开业折扣**，PERCENT 券本应可正常抵扣
- 但若后端仅以"活动是否在有效期"判定 `campaignDiscountRaw > 0`，会**错误地清零 PERCENT 券**

前端目前没有"本单是否真享开业折扣"的字段，无法预判也无法在 UI 上解释。

### 3.2 接口字段补充

`GET /api/v1/stores/:store_id/opening-info` 响应新增以下字段：

```jsonc
{
  // ... 原字段保留
  "discount_policy": "EVERY_ORDER",         // 或 "FIRST_ORDER_ONLY"
  "user_discount_used": false,              // FIRST_ORDER_ONLY 时：当前用户是否已用过开业折扣
  "user_discount_applicable": true,         // 综合判断后：当前用户本单是否还享开业折扣（前端只读这个）

  "points_policy": "EVERY_ORDER",           // 积分/金币同理（共用一个策略即可）
  "user_points_used": false,
  "user_points_applicable": true
}
```

### 3.3 字段语义

| 字段 | 类型 | 说明 |
|---|---|---|
| `discount_policy` | string | 折扣发放策略。`EVERY_ORDER` = 开业期内每单都享；`FIRST_ORDER_ONLY` = 每人限 1 单 |
| `user_discount_used` | bool | 仅 `FIRST_ORDER_ONLY` 时有意义：当前用户是否已用过开业折扣 |
| `user_discount_applicable` | bool | **前端只读这个字段**。后端综合 `policy + user_used + 活动是否生效 + days_left > 0` 后给出最终布尔值 |
| `points_policy` / `user_points_used` / `user_points_applicable` | - | 积分/金币同理 |

### 3.4 联动修正（重要）

补字段的同时，请同步修正以下计算路径，使其基于"**本单是否真享活动折扣**"判断，而非"活动是否在有效期"：

| 路径 | 文件位置（参考回执） | 期望行为 |
|---|---|---|
| `/orders/preview` 的 `campaign_discount` | `order/service.go:536` 附近 | `user_discount_applicable=false` 时返回 `campaign_discount=0` |
| `/orders/preview` 的"防折上折"判定 | `order/service.go:564-567` | `user_discount_applicable=false` 时，PERCENT 券**不应**被清零 |
| 下单 `CreateUserOrder` | `order/service.go:708` 附近 | 同上 |
| 收银端三处 | `cashier/service.go:489/752/993` | 同上 |
| `/coupons/available`（如已实现 `expected_discount`）| `marketing/service.go` | 同上：基于本单实际折扣判定 PERCENT 券是否可用 |

## 4. 兼容性

- 新字段名建议：`discount_policy` / `user_discount_applicable` / `points_policy` / `user_points_applicable`（snake_case）。
- 老版本前端忽略未知字段，不影响行为。
- 字段值建议固定为字符串 `"EVERY_ORDER"` / `"FIRST_ORDER_ONLY"`（不要用数字枚举，避免前端二次映射）。
- 若策略统一由后台配置（每个活动可不同），则 `policy` 字段从 `store_opening_configs` 表的实际配置读取；若产品上目前是固定策略（如全部 `FIRST_ORDER_ONLY`），可先硬编码返回，但字段必须暴露。

## 5. 前端落点（等后端字段上线后启用）

### 5.1 开业横幅（`pages/dinein/index.vue`）

- `user_discount_applicable=false` 时，"🏷️ 9% off" 那一行加灰色"已享"或"本单不享"标记。
- `user_points_applicable=false` 时，积分/金币行同理。
- `discount_policy=FIRST_ORDER_ONLY` 时，横幅顶部加小字提示"限首单享"。

### 5.2 结算页（`pages/checkout/index.vue`）

- `user_discount_applicable=false` 时，PERCENT 券应能正常抵扣（依赖后端 `expected_discount` / preview 修正）。
- 可选：UI 上单独展示"本单不享开业折扣"提示行。

前端会做向后兼容 —— 字段未返回时维持现状（横幅照常展示），不会报错。
