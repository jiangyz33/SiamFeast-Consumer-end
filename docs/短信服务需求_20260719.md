# SiamFeast 短信服务需求文档

> 项目:SiamFeast(泰国餐饮 APP)

> 收件人:后端 + 运维
> 发件人:前端 jiangyz33
> 目的:为 APP 提供短信验证码登录功能(泰国用户主推)

## 一、需求背景

### 1.1 为什么需要短信服务

泰国用户登录习惯(优先级):

| 登录方式 | 普及度 | 当前状态 |
|---|---|---|
| **手机号 + 短信验证码** | ⭐⭐⭐⭐⭐ | ❌ 缺短信服务 |
| Google 登录 | ⭐⭐⭐ | ✅ 已上线 |
| 邮箱 + 密码 | ⭐⭐ | ✅ 已上线 |
| Facebook 登录 | ⭐ | 暂未启用 |

**结论**:泰国用户最习惯手机号收码登录,**必须有短信服务**。

### 1.2 当前状态

- ✅ 后端 `/auth/sms/send` + `/auth/sms/login` 接口已实现
- ❌ **未配 SMS 服务商凭证**(Twilio Account SID / Auth Token / From Number)
- ✅ 后端配了**测试号码短路**(`+66811111111` / `+8613800138000`,code 固定 `123456`)

用户实际手机号收不到验证码 → 无法上线短信登录。

## 二、需要运维 + 后端做的事

### 🔴 运维提供(关键)

需要运维注册短信服务商账号,提供以下 3 个凭证:

```env
SF_SMS_PROVIDER=twilio                  # 短信服务商(twilio / aliyun_intl / stech_thailand)
SF_TWILIO_ACCOUNT_SID=ACxxxxxxxxxx      # Twilio 账号 SID
SF_TWILIO_AUTH_TOKEN=xxxxxxxxxxxx       # Twilio Auth Token
SF_TWILIO_FROM_NUMBER=+1XXXXXXXXXX      # Twilio 发送号码
```

### 🟡 后端配置(运维给凭证后)

后端只需把这 3 个值填到 `.env`,**不需要改代码**(已经预留好)。

### 🟢 前端(已完成)

`utils/sms.js` + `pages/login/sms.vue` 已就绪,等运维凭证就能开启短信登录。

## 五、最终推荐:Twilio

### 为什么选 Twilio

1. **运维注册门槛低**(邮箱 + 手机号即可)
2. **免费 $15 额度**,够测试 500 条短信
3. **API 文档完整**,后端集成简单
4. **全球覆盖**,以后做其他国家业务也能复用
5. **送达率达标**,泰国 95%+

### 不推荐泰国本地的理由

虽然便宜一半,但:
- ❌ 注册需要泰国手机号
- ❌ 文档泰文,沟通障碍
- ❌ 不支持支付宝,付款麻烦
- ❌ 早期阶段不值得为节省 ¥0.15/条承担这些成本

### 后续切换成本

如果未来用户量大,**可以无缝切换**:
- 后端抽象了 `SMSProvider` 接口
- 只需加一个新 Provider(如 `stech_thailand.go`)
- 改环境变量 `SF_SMS_PROVIDER=stech_thailand`
- 业务代码不变

## 六、运维操作步骤(以 Twilio 为例)

### Step 1:注册 Twilio 账号

1. 访问 https://www.twilio.com/try-twilio
2. 填邮箱、密码、姓名
3. 邮箱验证
4. 手机号验证(中国手机号可以)
5. 选 "I want to send SMS"

### Step 2:创建项目

1. Project Name:`SiamFeast`
2. Use case:`Verify Users`(短信验证)
3. 选语言:Node.js / Python(看后端用什么)

### Step 3:购买发送号码

1. Console → Phone Numbers → Buy a number
2. 国家选 **United States**(最便宜,可发国际)
3. 价格约 $1.15/月
4. 勾选 **SMS-capable**
5. 购买

或选 **泰国号码**:
- 价格 $1-3/月
- 泰国本地送达率最高
- 但**需要泰国营业执照**才能买

**推荐**:买美国号码即可(全球可发)。

### Step 4:记录 3 个凭证

在 Console 主页 → **Account Info**:

| 凭证 | 位置 |
|---|---|
| **Account SID** | Console 首页 `ACxxx...` |
| **Auth Token** | 点 "View" 显示 |
| **From Number** | Phone Numbers → Manage → Active numbers |

### Step 5:充值(从 Trial 升级)

1. Console → Billing → Add payment method
2. 信用卡 / PayPal
3. 充值 $20(约 500 条短信)
4. 自动从 Trial 升级为正式账号
5. 现在可以给任意号码发短信

### Step 6:配置环境变量

把 3 个凭证发给后端:

```env
SF_SMS_PROVIDER=twilio
SF_TWILIO_ACCOUNT_SID=ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
SF_TWILIO_AUTH_TOKEN=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
SF_TWILIO_FROM_NUMBER=+1XXXXXXXXXX
```

⚠️ **安全提示**:
- Auth Token 是高敏感凭证,绝不放前端 / 提交 git
- 通过 1Password / 企业 IM 加密给后端

## 七、后端验证流程

运维提供凭证后,后端验证:

### 7.1 测试发送(命令行)

```bash
# 直接调 Twilio API 测试
curl -X POST https://api.twilio.com/2010-04-01/Accounts/{AccountSID}/Messages.json \
  -u "{AccountSID}:{AuthToken}" \
  --data-urlencode "From=+1XXXXXXXXXX" \
  --data-urlencode "To=+6681XXXXXXX" \
  --data-urlencode "Body=Your SiamFeast code is 123456"
```

期望返回 `201 Created`,手机收到短信。

### 7.2 后端接口测试

```bash
# 调用后端 /auth/sms/send 接口
curl -X POST https://api.siamfeast.com/api/v1/auth/sms/send \
  -H "Content-Type: application/json" \
  -d '{"phone_number":"+6681XXXXXXX","scene":"login"}'

# 期望返回
# {"code":0,"data":{"expires_in":300,"is_test":false}}
```

手机应收到短信(6 位验证码)。

### 7.3 联调登录流程

1. APP 输入真实泰国手机号(如 `+66812345678`)
2. 点发送验证码
3. 后端调 Twilio 发短信
4. 手机收到 6 位码
5. APP 输入码 → 调 `/auth/sms/login`
6. 登录成功,拿到 JWT

## 九、安全与合规

### 9.1 防短信轰炸(已实现)

后端已有 4 重频控:

| 限制 | 阈值 |
|---|---|
| 同号码 60s 内 | 1 条 |
| 同号码 1 小时 | 5 条 |
| 同号码 1 天 | 10 条 |
| 同 IP 1 小时 | 10 条 |

### 9.2 防爆破(已实现)

- 同一验证码 5 次失败后失效
- 需重新发送

### 9.3 隐私合规

| 项 | 要求 |
|---|---|
| 手机号存储 | 明文(用于登录查询) |
| 日志脱敏 | 日志里只显示 `+66****5678` |
| 验证码 | Redis 存 5 分钟,验证后删除 |
| 用户授权 | 隐私政策需说明短信使用 |
