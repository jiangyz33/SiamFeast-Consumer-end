## 1. 问题

### 1.1 现象

C 端"我的券"列表（`pages/coupons/index.vue`）的"30-3优惠卷"（id=305）显示有效期是**空白**：

```html
<view class="coupon-validity">
    <text class="validity-text"><span></span></text>   ← 空
</view>
```

### 1.2 数据实证

```
GET /api/v1/coupons?status=all&page=1&page_size=20
```

返回的 user_coupon 字段（id=305）：

```json
{
  "id": 305,
  "coupon_id": ...,
  "name": "30-3优惠卷",
  "type": "FIXED",
  "value": 3,
  "status": "USED",
  "start_date": "2026-07-05T11:37:48...",   ← 模板字段（30 年占位）
  "end_date": "2056-07-05T11:37:48...",     ← 模板字段（30 年占位，不能展示）
  "claimed_at": "2026-08-02T23:31:47..."    ← 用户领取时间（真实）
}
```

**缺失的字段**：
- ❌ `valid_type`（FIXED / DAYS_AFTER_CLAIM）
- ❌ `valid_days`（DAYS_AFTER_CLAIM 时用于"领取后 N 天有效"展示）
- ❌ `valid_end`（FIXED 时的真实到期日）
- ❌ `valid_start`
- ❌ `expire_at`（用户实例的真实过期时间，领取时刻 + valid_days）
- ❌ `template`（空对象 `{}`）

### 1.3 对比：其他接口已正确

按 8-04 回执：
- `GET /coupons/newbie-pack` ✅ 已返回 `valid_type` / `valid_days`
- `GET /campaigns/:id/claimable-coupons` ✅ 已返回（ClaimableCoupon struct 本身不含 end_date）

**`/coupons`（我的券列表）接口漏了**，没走相同的 `toCouponItem` 转换。

## 3. 需求

### 3.1 `GET /api/v1/coupons` 响应每条 user_coupon 补全以下字段

| 字段 | 类型 | 取值 |
|---|---|---|
| `valid_type` | string | `FIXED` / `DAYS_AFTER_CLAIM`（来自券模板）|
| `valid_days` | number | DAYS_AFTER_CLAIM 时有值（如 30），FIXED 时省略 |
| `valid_start` | string \| null | FIXED 时 = 模板 start_date；DAYS_AFTER_CLAIM 时 null（omitempty）|
| `valid_end` | string \| null | FIXED 时 = 模板 end_date；DAYS_AFTER_CLAIM 时 null（omitempty）|
| `expire_at` | string | **用户实例的真实到期日**（领取时刻 + valid_days，或 FIXED 的 end_date）|
| `template` | object \| null | 可选：券模板对象（包含规则、icon 等，前端目前未使用，可省略）|

### 3.2 字段语义说明

- `valid_type` / `valid_days` / `valid_start` / `valid_end`：描述**券模板的有效期规则**
- `expire_at`：描述**用户领取后的实例真实到期日**（最实用的字段，前端可优先展示）

### 3.3 实现建议

复用 8-04 回执里的 `toCouponItem`（`internal/modules/marketing/service.go:2300`）逻辑，在 `/coupons` 接口的序列化路径上同样调用。具体后端文件位置需要后端自查（可能在 `internal/modules/marketing/coupon_repo.go` 或类似处）。

## 4. 前端落点（字段补全后即生效，无需改代码）

`pages/coupons/index.vue` `normalizeCoupon` 已就绪：

```js
const validType = (c.valid_type || tpl.valid_type || '').toUpperCase()
const validDays = Number(c.valid_days || tpl.valid_days || 0)
const validEnd = c.valid_end || ''
const validStart = c.valid_start || c.start_date || ''

let validity = ''
if (validType === 'DAYS_AFTER_CLAIM' && validDays > 0) {
    validity = this.i18n.t('coupons.validDays', { days: validDays })
} else if (validStart && validEnd) {
    validity = validStart + ' - ' + validEnd
} else if (validEnd) {
    validity = validEnd + ' ' + this.i18n.t('coupons.expireEnd')
}
```

后端补全后，三种类型都能正确展示：

| 券类型 | 后端字段 | 前端展示 |
|---|---|---|
| FIXED | `valid_start + valid_end` | 2026.07.05 - 2026.08.31 |
| DAYS_AFTER_CLAIM | `valid_days=30` | 领取后 30 天内有效 |
| 缺失（兜底）| 无 | 空（不会显示 2056）|

### 可选优化：用 `expire_at` 优先展示

前端可以进一步用 `expire_at` 显示**真实到期日**（不论类型）：

```js
if (c.expire_at) {
    validity = '有效期至 ' + formatDate(c.expire_at)
}
```

但这是产品决策 —— 是展示规则（"领取后 30 天"）还是展示真实日期（"2026-09-01 到期"）。建议两个都返回，前端按场景选。

## 6. 联调要点

- 字段类型严格按 JSON Schema：`valid_type` 字符串、`valid_days` 数字、日期 ISO 8601
- DAYS_AFTER_CLAIM 时 `valid_start` / `valid_end` 必须 omitempty（不是 null，是字段不存在）—— 否则前端误判会显示 2056
- `expire_at` 建议所有类型都返回（用户最关心真实到期日）
